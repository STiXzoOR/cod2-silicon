# Defined native boundaries follow-up

Updated 2026-11-05.

Eight assigned entries were revisited: **2 fixed, 5 intentional, 1 unchecked**. This follow-up covers EffectsCore/GenericParser2, gfx_d3d/r_staticmodelcache, gfx_d3d/r_xsurface, script/scr_compiler, script/scr_vm and xanim/xanim. It does not replace their module histories. Mac 1.3 i386 exact-symbol disassembly is the reference; no Windows behavior was inferred.

## Concrete notification corrections

`XAnimProcessServerNotify` (0x3ebbe) and `XAnimProcessClientNotify` (0x406f6) now retain the Mac first-note dispatch after its acceptance gates. At 0x3edd8–0x3ee40 and 0x40a97–0x40b90, an unordered new time passes the initial rejection comparisons, dispatches one note, and then stops when the next strict comparison fails. Native had retested the first note in a `while`/`for` condition and dispatched none. `XAnimSetTime`, `XAnimSetAnimRate` and the update callers do not establish a finite-only state contract. The native correction preserves the Mac branch behavior rather than adding a finite-value filter.

The client fraction calculation also retains the explicit addition of positive zero after subtraction, as at 0x40f49–0x40f5c and 0x40ff1–0x4100d. Omitting it could preserve a negative zero that Mac clears. The native arm64 object contains the corresponding zero-register `fadd`. End, composite, normal, wrapped, next-note selection, insertion ordering and fraction branches were compared, including ordered/unordered comparisons. All source changes are under `COD2_X64`; these corrections are compiled and reviewed, not specifically exercised by the existing fixtures.

## Intentional storage and representation boundaries

- `R_CacheStaticModelSurface` (0xe156a): positive paired copies, cache allocation and command submission match the inspected body. Mac 0xe170d–0xe172e enters the copy unconditionally and terminates only on equality. A zero or negative signed pair count therefore requires counter wrap, not one harmless padded copy. `XModelReadSurface` at 0xc73df–0xc7408 requests `6 * signedTriCount + 6` bytes; zero triangles request six bytes. The hunk's alignment does not authorize the billions of iterations or the cache-index writes. Native intentionally skips nonpositive pair counts. Loader padding of ordinary odd triangle counts remains unchanged.
- `XSurfaceGetVerts` (0xf9bca): rigid and weighted transforms, optional normal/UV handling, weight scales and SSE order were compared. Mac 0xf9c04/0xf9d6a accepts any nonzero signed vertex count and equality-terminates both loops (0xf9d49–0xf9d4f, 0xf9fd7–0xf9fe4). Negative counts require counter wrap and writes beyond the caller's storage. The loader allocates from signed counts (0xc73ba–0xc73c4), and the native bounds caller supplies a fixed 0xff78-byte vertex buffer. Native intentionally performs no vertex reads or output writes for negative counts; no arbitrary storage is fabricated.
- `ScriptCompile` (0x9a0ca): the complete original body never defines the payload at frame offset -0x20 before the final type-6 marker at 0x9a3d6–0x9a3ea. `SetVariableValue` at 0x917ab–0x917b3 copies it into the script variable. Native deliberately writes integer 1. The native `Scr_LoadScript` caller, compiler's far-call lookup and load-table cleanup were checked: they consume marker presence/type, not its integer payload. This is deterministic native initialization, not equality with old stack contents.
- `VM_Notify` (0x81cce): the complete notify body and its native cancellation, match, termination, queue and parameter-copy helpers were compared. Mac reallocation at 0x82407–0x8243b writes length, position, local ID and packed values but leaves the time byte at +0xa untouched. `MT_Alloc`/`MT_AllocIndex` (0x448ea/0x445b6) return reused arena buckets without clearing that byte. `VM_ArchiveStack` initializes the original byte at 0x810ac, and `VM_Resume` reads it in the timeout-reset comparison at 0x86b56. Native intentionally carries the old initialized time into the replacement stack. Timeout-reset decisions can differ from Mac allocation history; no claim of historical-byte parity is made.
- `XAnimGetNotifyFracServer` (0x41eda): child selection, next-note scan, signed cycle deltas and fraction arithmetic were compared. The no-match stores at 0x42048–0x42059 and server 0x3ee7a–0x3ee8e derive a short index from a null pointer minus the table address. Client 0x408f6–0x40904 similarly reconstructs an address from a truncated unsigned short. Native intentionally uses -1/end-fraction for server queries and returns without client dispatch when no next record exists. These choices also apply to the two corrected dispatch rows above. They replace address-dependent ILP32 behavior, including potentially in-storage accidental indices, rather than claiming the old result was always -1.

For ordinarily allocated clips (at most 254 file notes), Mac 0xba3cb–0xba415 and native `XAnimLoadFile` allocate `numNotes + 1` records and append `end` at time 1. Note times are finite unsigned-short frame ratios, or zero for a zero-frame clip (0xba603–0xba634). That guarantees a next candidate for time <= 1 and for NaN current time, whose scan comparison also accepts the sentinel. It does not prove a finite/ranged state contract for every caller. Empty/exhausted tables therefore retain the explicit native adaptation. The Mac wrapped-prefix loops have no count bound (server 0x3eca0–0x3ecfb; client stride two at 0x4115d–0x41187). Native preserves their in-storage order and client stride, while retaining its existing count bounds when the original would leave the table.

## Remaining unchecked entry

`GetToken` (0xab80c) still has no defined malformed-EOF replacement. Both the exact Mac body and native `GetToken_impl` scan through NUL in an end-of-line token (0xab95f–0xab999); an unterminated quoted token also leaves the cursor past NUL (0xaba0f–0xaba1f). The real FX loader at 0x5d25f–0x5d2b3 and native `FX_ParseEffectFile` request file length plus one and append one NUL, without a newline guarantee. `Hunk_AllocateTempMemoryInternal` (0x38192) has a preceding header, and its malloc fallback reserves the requested extent; neither supplies a readable terminator suffix. Whitespace/comments, quoting, signed-character comparisons, size limits, trimming and quote removal were hand-compared, but malformed EOF remains outside established storage on both sides. This row remains unchecked; no padding or arbitrary bytes were introduced.
