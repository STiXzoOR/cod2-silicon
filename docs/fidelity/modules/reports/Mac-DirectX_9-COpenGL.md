# Mac/DirectX 9/COpenGL reconciliation

Updated 2026-11-05. Reviewed all 36 assigned entries against the symbolized Mac 1.3 i386 binary and the selected native providers. 33 entries are reconciled: 6 equal and 27 fixed; 3 remain unchecked. Current GL remains selected; future Metal work is no exemption.

The empty native bodies now implement texture target/name caching and border colors (0x2007a, 0xe930, 0xe024), generic and fixed array state (0x20042–0x21370), texture matrices and generation (0x213d0–0x21b3c), binding release, shutdown and object lifetime. CTexUnit Reset at 0x20328 restores all three targets, filtering, LOD bias, fixed combiners, texture coordinates and temporary OpenGL-error inhibition. Init at 0x21c10 has a substantial native implementation, but is not claimed complete.

The appended native state preserves every existing COpenGLNative member offset. The only actual COpenGL allocation is its typed static singleton, so increasing sizeof does not overrun a literal allocation. CBaseVA and VAO layouts were checked against CVertexArrays.c, COpenGLVAO.c and CVAOPacket.c rather than applying i386 offsets to native pointers. The six combiner bodies actually live in CDirect3DDevice.c; their typed members, float scales and update order match their individual Mac entries.

Texture ownership was checked against the texture worker's actual CDirect3DCubeTexture.c and Device providers. The secondary prefix is two pointers, wraps/border/min/mag/last-level/anisotropy, then three dimensions. There is no reserved scalar after anisotropy. Native GLuint names are embedded in their owning texture or standalone surface allocation. Register keeps a non-owning pointer in a list and deduplicates by pointer identity. Release invalidates every cached reference, removes the node even for an already-zero name, deletes the GL name and zeroes it; it never frees the embedded GLuint. Shutdown deletes/zeroes live registered names, retains their registration and clears every cached name pointer. This last invalidation is essential because recreation reuses the same native pointer. The Mac instead owns separately allocated name cells. VAO registrations retain their existing heap-name ownership.

Init's light source aliases its destination in the original too: the loop passes this+0xbc+i*0xb4 (source at 0x22045, call at 0x2202e), which is the SetLight destination at 0x20fde–0x20fef. Consequently the original suppresses glLight calls while caching GL defaults; the native code keeps this quirk. The capability formerly read by CColorConverter at private offset 0x800 is the persistent GL_ATI_array_rev_comps_in_4_bytes result (0x21c5f), now a typed member, with its selected consumer updated.

The recovered constructor, light/dither/material setters and coalesced array callbacks are necessary provider dependencies but have catalog rows outside this unit; their statuses were not changed here. Coalesced callbacks were read from __TEXT,__textcoal_nt at 0x2ee846 onward. This does not reconcile all CVertexArrays or MacFastCopy rows. Existing COpenGLVertexProgram constructor/destructor behavior and STL placeholder exports outside these assigned rows were not reconciled.

Unresolved entries:

- 0x100ce SynchronizeD3DAndOpenGLTextureState: the actual native Device UpdateTextureIfNeeded/ApplySamplerState path covers typed targets, names, uploads and selected sampler settings, including the texture worker's zero-name recreation. The original full LOD/filter/cache transition contract and its corresponding Device caller identity remain unproved. The Device file was not edited by this unit.
- 0x20b00 SetVAO: binding, fixed/generic cache copies and invalidation were restored. Original offsets 8/c describe VARange start/size; current native VAO/CVAOPacket providers expose UINT32 mCode/mReserved0C and assign only zero. The code accepts the proven zero range and does not manufacture a native pointer from a nonzero scalar. A widened range provider remains missing.
- 0x21c10 Init: extension and GL defaults, owned arrays/lights/texture units, generic attributes and VAO setup were restored. Original 96 shader-constant dirty-cache entries and remaining private cache fields do not yet have a proven owned native provider. Native texture units retain the existing fixed capacity of 16 instead of the original dynamic vector. Neither Init nor Shutdown has a selected native Device caller beyond extern declarations; restoring these functions does not close Device lifecycle integration.

Arm64 Release cod2_macos_ded and the actual COpenGL, utility, fence, converter, rb_backend and rb_state renderer objects compiled at low priority with at most two jobs. All five OFF preprocessing configurations match the baseline, including actual __LINE__ expansions. No new tests, full CI or replays were run. Restored GL-state and combined texture/buffer lifecycle paths were compiled and reviewed, not exercised. Private evidence: ~/Library/Application Support/CoD2-native-decomp/recon-mac-gl.noindex/.
