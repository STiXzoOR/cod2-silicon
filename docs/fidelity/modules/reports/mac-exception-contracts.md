# Native mutex and Optimize exception contracts

Updated 2026-11-05. Three unchecked rows are fixed; the already-fixed deque initializer receives a failure-ownership correction without changing its normal-path verdict.

Exact Mac `CMutex::CMutex` at `0x1173fe-0x11747a` checks attribute initialization, recursive-type selection and mutex initialization in order. Every failure throws the returned signed 32-bit status; attribute destruction occurs only after success. The RTTI import at `0x1accc5d` is `__ZTIl`, so retail throws an i386 `long`. Native now checks each result and uses a typed C++ bridge to throw native `long` with the sign-extended status. Native `long` storage is wider; exception type and status value are preserved. The existing recursive-lock fixture passes with the SDK's recursive mutex constant.

Mac `Optimize` is bounded by true symbols `0x112c44-0x113174`. Its `0x113119` cleanup deletes remaining triangle nodes; `0x113166` first destroys the constructed deque, then joins that cleanup and resumes the same exception. Native C callbacks now run inside a C++ owner whose nonthrowing destructor performs those releases on return or unwind. The callback context remains in its caller's live frame. Triangle allocation is followed only by primitive tuple assignment and the allocation-free list hook before ownership transfers to the list.

The coalesced deque initializer is bounded by `0x2f0f1a-0x2f105c`. Its partial-block cleanup at `0x2f1009` and map release/reset at `0x2f102b` are now represented by a separate construction owner. A failed map allocation owns nothing; a failed block allocation deletes only completed blocks, then the map, and zeros map/mapSize. Optimize owns the deque only after initialization returns. Existing map growth and push-back helpers were read: failed growth retains the old map; successful growth followed by a failed block allocation leaves the relocated active range valid. No helper edits beyond the initializer were needed.

The actual native C compile commands now include source-scoped `-fexceptions`; emitted IR no longer marks these C frames `nounwind`. The C++ bridge has cleanup/resume IR and native personality/LSDA metadata. All three changed client objects and the dedicated target compile. Existing `cpp_abi`, `threads_ring` and VAO `gl_state` fixtures pass under ASan/UBSan. No tests, cases or assertions were added. The allocation-visible output order is also corrected.
