# Mac/DirectX 9/MacOpenGLUtils reconciliation

Updated 2026-11-05. All 27 assigned entries were compared with Mac 1.3 and their actual native providers. 26 are reconciled: 15 equal, 8 fixed, 3 intentional; StretchRect remains unchecked.

The utility tables were decoded directly from binary data: all 8 declaration words, 32 primitive-count translation bytes and 16 texture-operation words match. The format-bit switch, DXT block sizing, mip-count loop, texture arguments, declaration extraction and low-precision square root were read by hand. GetImageSizeInBytes at 0x25632 stops once all dimensions reach zero; native previously continued adding artificial 1x1 levels. GetOpenGLTextureType at 0x25148 preserves its input create-resources flag except for disabled depth formats, instead of forcing true. Native null-output handling, byte-oriented BGRA uploads and supported A8/A8L8 mappings remain explicit native storage adaptations. The texture worker separately provides safe backing for overspecified extra child levels.

ConvertD3DProjectionMatrixToOpenGL at 0x254f6 now keeps the original negative-product/add order for m[10]. Its native +1/-1 projection numerator and GetSubPixelOffset's zero offsets remain the existing measured integer-pixel-center adaptation described in the F2 post-processing reports. No old GPU-specific offsets were restored globally.

Four attributed ARGB rows actually live in CColorConverter.c. Std conversion at 0xceda/0xd04a rotates the packed word right by 8; native byte-swapped it, exchanging channels. The native helper is corrected. ATI conversion at 0xd210/0xd380 already rotates right by 24 and matches. The additional GetColorConverter typed capability consumer is outside this unit's ledger; its status was not changed.

Six attributed renderer rows were independently read against the final backend source at df8d9cc, not inferred from their module names. BeginViewCmd at 0xd51f4 matches the command copies, viewport update, projection-distance normalization and matrix constants. GaussianFilter2D at 0x105ac0 matches the eight symmetric taps, weights, material and destination fields; native exact-target UV extent is intentional. ApplyGlowFilter at 0x1060de matches radius scaling, optional setup pass, chain budget, pass accounting and ping-pong selection, with the existing exact-target UV and pixel-edge compensation retained.

LatePostEffectsCmd at 0xda2f6 had deterministic glow errors. Mac 0xda6ae–0xda6e1 and 0xdb06a sorts the two radii, records the original dvar index as 0/1, and reads feedback images by pass ordinal (0xda81f). Native used integer bit tests, omitted the nonzero-radius sort, used a pass count as a dvar index and selected feedback images by that index. The restored float sorting and separate indices also preserve skybleed-only eligibility when GfxWorld.skyImage is present (0xdb0a8); this is a typed world field, not a private material offset. Existing defined native debug colors are retained where the Mac reads indeterminate scratch color bytes. Native final-composition orientation and exact target extents remain intentional.

SavedScreen blend at 0xd968e matches fade bounds, double pow input, alpha clamp/rounding, byte packing and command advancement. Its native Apple UV extent now follows the actual exact-size saved-screen target allocated by R_InitFullscreenRenderTargetImage/Image_SetupRenderTarget; using the original POT denominator cropped NPOT native targets. UpdateViewportConstants at 0xce6c6 now multiplies inverse dimension by viewport size before halving, matching SSE order. Its native full-target extents remain intentional.

Unresolved: StretchRect at 0x17c74. The selected Device provider handles the equal-size backbuffer copy and cinematic quad, but the original also supports surface destinations/rectangles, maintains GL/client/matrix state and restores sampler state. The native fallback ignores destination-surface and filter semantics and leaves state changed. No speculative Device-layout implementation was added; the pending Device provider does not prove this complete.

Arm64 Release dedicated target and actual changed renderer objects compiled at low priority, at most two jobs. All five OFF preprocessing configurations, including actual __LINE__, match baseline. The existing post-effects fixture passed native-extent, below-threshold and above-threshold cases under ASan/UBSan; these exercise blur, not the corrected glow sorting or saved-screen blend command. The existing saved-screen CGL fixture passed framebuffer pixels, orientation and GL state under ASan/UBSan; it checks only the production Device copy, not the changed blend command. No new tests, full CI or replays were run. Corrections beyond those existing fixture paths are compiled and reviewed, not exercised. Private evidence: ~/Library/Application Support/CoD2-native-decomp/recon-mac-gl.noindex/.
