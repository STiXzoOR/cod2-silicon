# gfx_d3d/r_rendercmds module reconciliation

Updated 2026-11-05.

**41/42 reconciled: 17 equal, 3 fixed, 21 intentional, 1 unchecked.** Mac 1.3 i386 is the authority. Each assigned entry was read against its original body; temporary-skin helpers have live inline providers in r_init.c. Triage and constants were supplementary checks. The frontend dispatch table at 0x32aac0 and the light/LOD dvar import slots were decoded directly.

R_EndDelayedDrawing at 0xc813a emits a RETURN and patches its opening GOTO to the following record. The native version still appended four bytes, although every other native allocator rounds records to eight bytes. That put subsequent GfxCmdCall and pointer payloads at misaligned addresses. RETURN now uses the native critical allocator, preserving its failure target and the full-width subCmd field.

R_AbortRenderCommands at 0xc78f0 only unlocks the cache and clears command usage. Native additionally decommitted temporary skin storage. That extra release is removed. R_InitBackendData at 0xc7d38 omitted the pending temporary-skin decommit before reusing the static frontend. It now performs that release before advancing the frame. Native Apple initialization and frame end select pool[0] and set dynamicBufferFrame to zero, as 0xc7db3 and 0xc7f5b do; native previously rotated two caches. Frame-end temporary-skin release also now precedes the new frame state, as 0xc8038 does. The native scratch buffer and its position remain owned by DxGlobals, which is also the active r_model producer's owner.

The actual arm64 compiler layouts were compared with the typed consumers in pending backend df8d9cc. GfxCmdCall is 16 bytes with subCmd at 8; light properties are 80 bytes with lightDef at 72; BeginView is 64 bytes with sceneDef at 8 and viewParms at 32. Stretch/rotated pictures are 56 bytes, raw pictures 48, quad pictures 56, sprites 48, fullscreen quads 40 and draw surfaces 24. Both inline text payloads start at 52. Nonpointer payloads retain their fields and receive trailing alignment padding where necessary. Text storage uses the actual text offset and a NUL terminator, with the existing native 16-bit aligned-record limit. These storage and capacity adaptations are recorded as intentional, rather than claiming i386 byte parity. The unused material tail in BlendSavedScreen remains untouched; the actual consumer selects its material from rgp.

Typed static backend/debug storage is large enough for the native records. BeginView, pictures, text, light properties, GOTO and CALL consumers read the same declared fields and advance through byteCount. The pending GL cd687d6 and device 9f05cde providers were read as dependencies; future Metal documentation is not a replacement for these active commands. Pending buffer 6b40401 makes DISCARD flags functional: it retires dynamic storage for two frames and recreates it. Parent follow-up 33c898e was read directly: native Apple R_LockSkinnedCache now passes the unconditional 0x2000 at Mac 0xd0054, ignoring its extra native lockType argument. That follow-up must integrate with the buffer provider before this unit. The earlier provider that ignored Flags is not the integrated ownership contract. The frame worker owns the separate buffer allocation/release correction; selecting the already allocated first pool here is safe before that reduction.

R_EndFrame remains unchecked. The local ownership/order corrections are compiled and reviewed, but native still prepends RB_AdaptiveGpuSyncTarget. Pending RB_ExecuteRenderCommands lacks the original mode-3 elapsed-budget logic at 0xd93b3/0xd94a2 and has zero mode-2 timing. The extra frontend call currently tests/deletes the previous fence in mode 0; removing it alone can let the backend overwrite g_FenceID. Shared callback, clock-unit and fence-retirement reconciliation is required. Neither the absence of the call from this Mac body nor unrelated pending fixes establishes whole-frame parity.
