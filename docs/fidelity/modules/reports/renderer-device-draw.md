## Driver repairs

The normal native route now runs the original fixed/FVF or programmable validator chain, instead of rebuilding arrays and transforms from stride/material guesses. Mac 0x120a6 validates modelview first. Base changes update the retained base word. Normal and scanned low/high bounds add base exactly as 0x120fc–0x12117 and 0x12203–0x12233 do. Raw ushort indices still begin at `data + startIndex*2`; range hints include base separately. The original always consumes ushort indices even if the buffer records another format. Validation receives `high-low+1`, while raster receives `base + (high-low+1)`, rather than `high+1`. Packet range arithmetic stays in the reviewed widened provider.

Mac 0x12124 forces transformation validation on every call. Transformation/raster flags clear only after raster validation, and the common return at 0x1218f resets the draw byte. Raster can clear that byte without cancelling the current normal-path submission; its original batch loop does not reread it. Only GL mode 4 draws; other primitive modes retain element-count/range/fence/return behavior. Normal submission follows 0x1233c–0x12397 in chunks of at most 65,535 elements, using the same raw index pointer and range hints.

Original blend dispatch at 0x122a2–0x122f0 now consumes the mapped GL factors and dirty byte supplied by the separately owned render-state prerequisite. The point byte read at 0x12305 brackets drawing with sizes 2 and 1 (0x12450/0x1232b). Typed accessors expose the native program owner and trailing byte without assuming original offsets. Constructor 0x1f96c initializes the corresponding original trailing byte to zero; the native constructor/layout remain unchanged.

The fence tail at 0x12143–0x121eb and 0x1246a now AddRefs/Releases stream zero, skips usage bits 0x200/0x8 and calls the actual fence provider. Programmable position metadata selects its declared buffer, then adds declared offset, base*stride, **stream-zero offset again**, and MinVertexIndex*stride. Fixed position already includes base, so its tail adds only MinVertexIndex*stride. Sizes use the computed range count. The unusual extra stream-zero offset is preserved, not normalized. CPU scratch remains owned by its existing allocator, and submission finishes before cleanup. No borrowed COM ownership or packet lifetime was changed.

## Native boundaries and restoration

The licensed-cache option and explicit `D3D_PROG=0` approximation remain authoritative. The CPU approximation preserves its matrix, texture/lightmap, color-order and shader-selection policy during submission. Its temporary depth/cull/fog/light/alpha/color/blend/program states, texture environments and client arrays are now scoped. Modelview, projection and the two touched texture matrices are stored/restored independently in double precision; ARB program bindings are explicit. The common caller always closes the scope after the approximation returns, including its early returns. It does not restore the original draw/validation bytes: their driver sequencing and point/fence tail remain as above. The duplicate core VAO bind that raised GL_INVALID_OPERATION in the legacy context is removed; client arrays use APPLE VAO0 and zero array/element buffers.

The GL-owned stacks provide context-state restoration, rather than copying COpenGLNative, CTexUnit, COM objects or packet owners. The required behavior is specified by [OpenGL 2.0 section 6.1](https://registry.khronos.org/OpenGL/specs/gl/glspec20.pdf), [ARB_vertex_program](https://registry.khronos.org/OpenGL/extensions/ARB/ARB_vertex_program.txt), [ARB_vertex_buffer_object](https://registry.khronos.org/OpenGL/extensions/ARB/ARB_vertex_buffer_object.txt) and [APPLE_vertex_array_object](https://registry.khronos.org/OpenGL/extensions/APPLE/APPLE_vertex_array_object.txt): current generic values and client buffer/array bindings have attribute groups, APPLE client restoration binds the saved VAO first, while matrices and program bindings require separate handling. The selected display requests an OpenGL 2.1 compatibility context. This is not a core-profile implementation.

Texture state needs an additional object journal: GL_TEXTURE_BIT covers only objects bound at the push, whereas approximation can substitute another base texture or lightmap. ApplySamplerState records each selected object after its pending uploads and before sampler writes. It restores wrap/filter/max-level/border/anisotropy and the corresponding native sampler scalar fields. The journal borrows texture-info addresses only through the synchronous draw; selected constructors keep embedded name addresses stable, selected upload/count methods do not release objects, and bound/material textures retain their existing ownership. New names, texture contents, dirty/upload completion, registration lists and COM references remain live. No owner or allocator layout is rolled back.

Logical caches restore their own entry values independently of actual GL state. This preserves deliberate temporary pixel/copy overrides. Only touched modelview/selector/program/target/sampler scalar fields are copied. Borrowed name-cache identities are checkpointed individually: unchanged embedded name values retain their cache identity, while a generated name invalidates the old cache entry so its next consumer binds it. The owning binding lists, texture name fields, array pointers and packet storage are never copied as a struct. Original array objects are restored by the GL client stack. The previous directStateDirty latch is removed, allowing normal routes to resume immediately.

Extended native formats 8–12 retain their typed normalization, color conversion, attribute mapping, widened base arithmetic and skip policy. They now supply only VAO0 arrays to the same original program/raster/lighting/blend/batch driver, instead of a second renderer that overrides those server states and tests a different draw byte. Default unused attributes are scoped with current/material state immediately around submission. Register-zero metadata is collected from the actual extended position element for the common fence. No old native ARB packet branch remains active; legacy OFF helper text is preserved.

Existing initialized device/packet storage remains. The inherited extended-color alias was corrected during review: the original adapter returned one process-global conversion buffer for every D3DCOLOR attribute, so a second conversion replaced bytes already bound by the first. Extended attributes now copy the converter's written span immediately into independent per-attribute buffers owned by DeviceStreamsNative. The original byte-order selector, requested-count/index-minimum lower bound, index-maximum upper bound, raw index offsets, NULL fallback and zero-stride converted-array binding are retained. Newly allocated unused prefixes are zeroed; unconverted scratch prefixes are never copied.

This storage is separate from convertedColors[16]. Normal converted colors force generic rather than static cached VAOs, but generic packet descriptors and COpenGL array state retain those normal pointers after submission. Extended-path reallocations therefore never touch that bank. Only APPLE VAO0 receives extended buffer pointers; its arrays are disabled/replaced before another extended setup, and g_VAOID forces the next normal packet bind. CPU approximation also uses a different buffer, so its conversion cannot invalidate extended pointers saved by the client-state scope. ResetStreamsNative frees both independently owned banks. Multiple converted colors and reallocations across these paths were compiled and reviewed, not exercised by the existing fixture.

Null/malformed buffers and primitives retain bounded native handling, and an empty special-index span avoids the original unconditional first-index read into potentially unreadable/indeterminate storage. These are intentional native storage contracts, not reproductions of invalid Mac memory reads.

## Verification and limits

The final actual Apple SDK arm64 Release Device object compiles. All eighteen existing depth-surface cases pass with AddressSanitizer and UndefinedBehaviorSanitizer: nine ARB cases and nine explicit fallback cases. Fallback uses the production approximation and its restoration scope. No test, case, assertion, setup or oracle was added or changed. Five inactive source configurations and actual line expansions match base 7f327b9; changed production files have no __LINE__ use. No full CI or replay ran in this unit.

Those cases exercise color/depth/stencil/effective-state behavior, including repeated fallback draws. They do not separately exercise a fallback-to-normal transition, sampled-texture journal entries, extended formats, multiple converted D3DCOLOR attributes or their allocation/reallocation/reset branches, nonzero base, nonzero point byte, enabled-light math or fence reuse. Those paths are compiled and reviewed only. The restoration contract is established from the full native call/storage graph and GL state rules; the eighteen cases are not presented as whole rendering coverage. Approximation output is explicitly not claimed equivalent to original licensed shaders.

The renderer owns a compatibility context with the ARB programs already required by the existing draw path. Each new scope consumes one server entry, and approximation also one client entry, without matrix-stack pushes. Active texture-view, screenshot, stretch and presentation/gamma stack scopes do not reenter indexed draw; selected texture upload/count methods do not recurse into it. GL guarantees at least sixteen entries. Arbitrarily exhausted external stacks or a foreign/core context are outside this bounded renderer contract; their limits were not newly measured. Existing GL errors are never cleared to mask a state failure.
