# Scanner descriptor lifetime

Updated 2026-11-05. Supplemental owner review for `ScriptParse` (`mac:0x00110220`); the prior scanner API investigation is unchanged.

Mac `ScriptParse` installs its automatic `buffer_state` in `yy_current_buffer` at 0x1102b6 and retains that address when it returns at 0x1102d6–0x1102d7. A later call can reuse the stack address. The comparison at 0x110299 then takes the alias path, which reads the new descriptor's uninitialized `yy_input_file` at 0x1102f6 before assigning it at 0x1102a1. The native C reconstruction inherited both the expired descriptor pointer and the uninitialized read. Its transient `yyin` value is overwritten by scanner initialization before I/O; this review establishes an undefined lifetime/read, not a demonstrated parser-output or gameplay failure.

Under `COD2_X64`, the descriptor now has static storage duration. It remains live through normal return and nonlocal exits, and its input-file field is initialized even on the alias path. The existing assignments still reset all ten fields before `yyparse`; token handling, source positions, result propagation and allocation order are unchanged. The scanner was already non-reentrant through its globals and static character buffer. The legacy automatic declaration remains under `#else`. This is an intentional native storage adaptation, not a claim to reproduce indeterminate stack contents.

Both production callers use this owner: `Scr_LoadScript` and the native debugger's `Scr_CompileTextInternal` set `scrCompilePub.in_ptr/parseBuf` and call `ScriptParse`. The descriptor's file field is set to NULL before parsing; scanner initialization reloads it, and refill reads script bytes through `Scr_ScanFile`. Evaluation-mode `CompileError` records its message and returns. Ordinary compilation errors call `Com_Error(5)` (Mac 0x9b803–0x9b812), which transfers to the frame recovery point through `longjmp` (0x2e3af–0x2e3c6). Native VM error checkpoints restore interpreter state, not scanner descriptors. A cleanup statement after `yyparse` would therefore miss nonlocal exits; persistent descriptor storage needs no cleanup hook.

`yy_create_buffer` is unchanged. It allocates a separate descriptor and character storage, with optional later character-storage reallocation. Production has no descriptor free operation. After this repair, `yy_current_buffer` names either the live static descriptor or a still-allocated heap descriptor, so a fresh successful descriptor allocation cannot match that address and take the allocator's pre-assignment alias read. Existing isolated scanner fixtures release their heap descriptors only as each process exits. This reasoning does not create a public deletion contract, free an original heap buffer, or reconcile unresolved scanner APIs.

Stock and CoD2x configured Release scanner objects compile. Four existing parser fixtures pass under ASan/UBSan in both configurations: native nodes, parser-stack growth, bad syntax and unexpected EOF. The syntax/EOF fixtures exercise nonlocal exits, but none performs a second parse after recovery; the lifetime correction is established structurally and reviewed, without a new regression case. The same four stock fixtures passed before the change. No tests, cases or assertions were added or modified, and no full CI or replay ran.

The source-guard audit reports only the enabled native configuration changed. All five inactive configurations also match with actual `__LINE__` expansion preserved. No diagnostic line-map reset is needed: the changed owner and its included implementation do not use `__LINE__`.
