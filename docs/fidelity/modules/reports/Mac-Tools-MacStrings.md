# Mac/Tools/MacStrings reconciliation

Updated 2026-11-05. **2/2 fixed**, with explicit storage adaptations below. Exact-symbol Mac disassembly is the authority.

GetCString at 0xa144 clears the output, constructs a CFString from the HFS length/UTF-16 array, converts it with encoding zero and signed-short capacity, and releases the created string. Native selected a constant-NULL CFStringCreateWithCharacters stub and an unprototyped int declaration. The Apple COD2_X64 branch now includes SDK declarations directly, and exactly that no-op constructor export is excluded. CFStringGetCString and CFRelease were already SDK-owned in the native graph. The HFS length/array layout and signed-short conversion remain the same. Source search found this is the only constructor caller, with no active engine call to either MacStrings wrapper.

CopyAndClean at 0xa1ac was empty. Native now follows its ordinary positive-capacity byte loop: discard LF without changing state, collapse spaces, turn the first CR into a space, emit two CR bytes for a subsequent CR, and preserve the separate space/CR state decisions. Ordinary characters clear both states. The signed-short capacity convention is retained. Mac can emit both CRs when only one payload byte remains, then write its terminator beyond the supplied capacity. Native caps that exceptional pair and always terminates inside positive-capacity output; nonpositive signed capacities return without writing. These are defined storage adaptations, not equivalence for overflowing or negative-capacity inputs. Overlapping source/destination behavior and malformed HFS lengths are not certified.

Both changed files preserve all five inactive guard configurations; neither uses line-number diagnostics. The complete arm64 dedicated target builds, including the actual MacStrings translation unit. As these helpers have no live native callers, dead stripping removes them from that executable. A link-only dynamic library built from the exact production object confirms all three CF calls import CoreFoundation, and the native stub object has no CFStringCreateWithCharacters definition. No test harness or runtime call was added. Triage reported no call/string differences; literal comparison needed explicit Mac address ranges and misses character-literal constants, so the full manual comparison controls the verdict. These corrections are compiled and reviewed only, pending independent review and integrated validation.
