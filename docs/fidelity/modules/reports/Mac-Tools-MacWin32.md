# Mac/Tools/MacWin32 reconciliation

Updated 2026-11-05.

18/18 reconciled: 7 equal, 3 fixed, 8 intentional. Read Mac 1.3 bodies, restarting exact-symbol disassembly for the misaligned timer entries. Checked the live Apple providers and their callers rather than assuming the old Win32 names imply SDK calls.

Mac 0xb35c rounds `(Microseconds + 500) / 1000`; native previously truncated milliseconds. The Apple monotonic provider now converts to microseconds before applying that rounding. Mac 0xae74 reports a frequency of 1000000 and 0xb3a8 supplies microsecond counts; native previously supplied a consistent but different nanosecond pair. Both now use the Mac units. Windows uses WINMM timeGetTime directly, including call 0x4479b1; the native clock still uses mach_absolute_time through MacSystem_Nanoseconds.

Mac MessageBoxA 0xae90 asks the user and returns 1/2/6/7 for OK/Cancel/Yes/No. The native shim previously always accepted questions. Client calls now use SDL_ShowMessageBox with those IDs, the first or requested second default button, and escape handling. Windows calls imported USER32 MessageBoxA at 0x46448d and 0x46459b, then explicitly compares the result to 6. SDL documents this API as usable before SDL_Init. The live startup/error path runs from linux_common main through WinMain on the main thread; the shim avoids invoking the UI from another thread. Dedicated, unavailable-display and off-main-thread calls write to stderr and return Cancel/No for questions. This explicit headless adaptation and the replacement of Carbon text cleaning/cursor guards are intentional. No dialog was exercised.

The VirtualAlloc/VirtualFree adapter still pairs calloc/free and preserves the Mac ignored flags and release-type check. GetFileAttributesA still uses MacFiles_access(path,4) and returns -1/1. The 32-bit atomic add matches. Native exchange and compare-exchange intentionally use compiler atomic semantics rather than Carbon's single-attempt/failure-result quirks; renderer cull-state callers depend on the standard contract. Windows calls imported InterlockedExchange at 0x462487. No Windows inlined compare-exchange body was identified, so that row claims an explicit native adapter, not Windows instruction equality.

Native input uses SDL keys and text events; MapVirtualKeyA's legacy compatibility switch equals the decoded default Mac key table but does not implement the old French/German Carbon tables. Windows calls its host MapVirtualKeyA at 0x468d74 with type 2. Native display callers bypass the unused fixed-size GetSystemMetrics shim. FindNextFileA uses a paired POSIX DIR/FFState provider; the old Carbon vector's iteration order, UTC timestamp fields and suffix filter are not claimed equivalent. Live Sys_ListFiles owns POSIX enumeration directly. Native thread IDs use pthread_mach_thread_np rather than truncating an opaque LP64 pthread pointer; sleep uses retrying nanosleep rather than Carbon MPDelayUntil.

Clipboard context was inspected only: mac_main Sys_GetClipboardData returns an empty static literal and Field_PasteClipboard passes the result to Z_FreeInternal. That inherited ownership boundary belongs to the unix/lifecycle owner; its pending e423a2a returns owned empty storage. This unit implements no clipboard content support.

The arm64 Release dedicated target built, and the client MacWin32 translation unit compiled with its actual SDL target command. Changes are compiled and reviewed, not exercised. Fifteen OFF preprocessor comparisons across the three changed sources match the base; none uses __LINE__. No new tests, full CI, replay, or application launch ran. Evidence is in the private recon-mac-win32.noindex directory.

Parent integration checks initially failed compiling the existing threads_ring fixture because its target did not carry the new SDL header/link dependency. The target now links SDL2::SDL2; no fixture cases or assertions changed. Existing Debug ASan/UBSan threads_ring and three system/network fixtures pass. The original failed build log is retained. These checks exercise ring wrapping and timer ratios, but no dialog UI or new failure path.
