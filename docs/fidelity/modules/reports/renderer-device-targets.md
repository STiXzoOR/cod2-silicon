## Corrections

Mac `SetRenderTarget` at 0x15500 resolves the previous auxiliary target, releases it, retains the new target and resets the viewport. Passing NULL retains the current target and still resets the viewport. Native previously replaced the pointer without ownership and used only a partial copy. The native setter now follows that sequence. `SetDepthStencilSurface` at 0xdce0 now releases and retains its current COM surface too. The default-depth getter's original separate-default-surface quirk is preserved.

Mac `Clear` at 0x141b0 clears transparent black normally, confines the operation to the cached viewport using the target's height, and restores depth enable/function, dither and write masks. Native previously skipped a color-only transparent-black clear and omitted that viewport and restoration work. Rectangle arrays remain ignored, as in Mac.

`StartPixelOneToOneState` at 0x13774 and `EndPixelOneToOneState` at 0x17924 now perform the temporary overrides and cache-based restoration. They bypass Device's cache-writing GL wrappers. The missing native dither and shade-mode state setters were added as prerequisites, checked against 0x15fd3–0x15ff0 and 0x1611a–0x1614b. This is a partial prerequisite fix; it does not reconcile the whole `SetRenderState` entry. Lifecycle integration supplies the original shade-mode 2/dither-off defaults, confirmed at Reset 0x1a54d/0x1a575 and constructor 0x1aa16/0x1aa3e.

`CopyColorToRenderTargetTexture` at 0x14754 is no longer empty. It copies the auxiliary content and implements the conditional shadow-cookie blur, both passes per requested count, the five verified weights and tap order, and the associated matrix, combiner, shader, mask and capability restoration. The weights at 0x3267ec and dispatch table at 0x326800 were decoded. Mac's repeated S-texgen test and final identity texture matrix are preserved. Native matrix-mode bookkeeping follows the raw path's final TEXTURE mode so the next cache-writing wrapper cannot skip a necessary mode change; the original texture-matrix cache quirk remains.

## Native and Windows boundaries

The SDL context owns the initial depth attachment even while the default COM depth pointer is NULL. Native keeps that defined initial depth active until an explicit `SetDepthStencilSurface(NULL)`. Mac's clear/end checks instead test its current COM pointer. The depth setter, clear and pixel-state end entries are therefore intentional adaptations, with COM ownership and requested-state transitions repaired. This work does not claim pixel parity for arbitrary nondefault depth backing.

The typed surface accessor uses the actual native Surface and secondary `COpenGLTextureStateNative` providers. It checks the surface vtable and exposes owner, name, target, mip, logical extent and row provenance. It never writes an original i386 offset. Native textures use synchronous logical-size allocations; copying Mac's power-of-two client-storage extent could exceed those allocations. Copies use logical extents. A native Surface padding byte records bottom-up GPU copies without enlarging the existing 128-byte allocation. Actual framebuffer writes mark that provenance and clear CPU dirty state. Actual CPU uploads reset it in both Surface image creation and subimage update; Surface/Texture unlock, texture preload/update and recreation all reach these upload functions. Pending AddDirtyRect/lock state alone does not reset provenance. Stretch uploads only a dirty source, because an unconditional upload would replace GPU content with stale CPU storage. The copy row is intentional at this storage boundary.

Mac `StretchRect` at 0x17c74 never loads either rectangle or Filter and forces linear filtering. Windows renderer `gfx_d3d_mp_x86_s.dll` has a live cinematic caller at 0x1002f410: 0x1002f622–0x1002f640 constructs the destination rectangle, 0x1002f642 passes filter 2, and 0x1002f663 calls Device slot +0x88. Native preserves the Windows rectangle/filter contract under the project's Windows-preferred policy. NULL selects a full surface; NONE/POINT use nearest and LINEAR uses linear filtering. This is supported by Microsoft's [StretchRect documentation](https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3ddevice9-stretchrect), not a claim to have decompiled the external D3D9 implementation.

The existing full-size backbuffer fast copy remains. Drawn copies now select the backbuffer or mapped AUX0/AUX1 staging attachment, copy into the destination texture, and restore touched sampler object parameters, GL/client attributes and matrices without changing persistent caches. A still-current auxiliary source is resolved before changing draw selection, without invoking shadow-blur side effects or stale CPU uploads. Inactive texture destinations use the opposite AUX attachment so the current surface's pixels survive; `RB_SetRenderTarget` already resolves a previous AUX before switching, so the inactive attachment is native scratch. Windows rectangle draws temporarily set a surface-sized viewport and disable scissor. The display provider already owns three attachments and maps BACK/AUX0/AUX1; no new FBO, Device storage or Metal path was introduced.

The staging follow-up explicitly selects BACK when the named source is the backbuffer, including when another target is current. The fast path saves/restores the actual read buffer, and drawn copies use the existing attribute restoration. Scratch selection follows the actual draw attachment: current AUX0 uses AUX1, current AUX1 uses AUX0, and only current BACK defaults to AUX1. A backbuffer source cannot override that preservation priority. Current-AUX resolves explicitly select the captured draw attachment for reading. Unknown staging selections return INVALIDCALL before GL changes. The existing saved-screen fixture's BACK/AUX shim was corrected to map its FBO attachments, matching the production context; its former passthrough reported GL_INVALID_OPERATION once explicit BACK selection reached it. Existing assertions and case counts are unchanged.

Source row conversion now follows stored provenance instead of whether the source happens to be current, so resolving and switching away from an AUX target does not change its later Stretch orientation. A current AUX destination is drawn into its own attachment and its full logical color extent is then resolved into its texture, preserving the result across the next target switch. It bypasses the texture-only fast copy. An inactive destination supports partial writes only when its existing texture is already bottom-up GPU content with no pending CPU upload; mixing untouched top-down CPU rows with new framebuffer rows returns INVALIDCALL. Full inactive-destination overwrites and cinematic rectangles into BACK remain supported. All five engine calls use full texture destinations; the only destination rectangle is the CPU cinematic-to-BACK path.

Supported Stretch surfaces are native, non-multisampled, uncompressed 2D color surfaces at mip 0; auxiliary destinations must fit the backbuffer staging extent and current AUX surfaces require a recognized active AUX attachment. Descriptor failures propagate. Depth, compressed, cube, nonzero-mip, multisample, same-surface, oversized staging and unsupported partial CPU-destination requests return INVALIDCALL. The five engine callers in `rb_backend.c` use filter 2, level-0 color images, full/downsampled screen targets, or the one-level cinematic texture. This is not general D3D9 driver support.
