# Config Studio: SwiftUI implementation contract

7 October 2026. This maps the approved canvas to production views; it does not claim those screens are implemented. The behavior spec is [Config Studio](../superpowers/specs/2026-10-06-config-studio-design.md). Visual authority is the [Design Rules and Config Studio boards](https://claude.ai/artifact/XZmUZKarMJWQ2Qa8NThzdh#page-dcb81aee8d83), inspected from the local saved canvas. Design Rules wins on appearance; verified engine/catalog facts win over sample board values and copy.

## Shared structure

Keep the existing launcher sidebar and add Configs between Library and Settings. Configs contains a 252-point ideal middle column (My loadouts, New loadout, Discover → Players/Saved) and a detail column. Selected loadout and active-for-next-game loadout are separate states. Selecting an item never changes the active profile. A loadout header shows its real name, provenance, last change and active state, with “Use for next game” only when applicable.

The loadout toolbar has Settings, Binds, Check-up and History, in one segmented navigation group. Settings owns Guided/Expert; Binds independently owns List/Visual. Preserve these preferences and selected purpose group as people move between loadouts. The eight groups are Frame & movement, Aim & input, Network, Visibility, HUD & crosshair, Audio, Graphics, Other. Counts come from the current catalog and filters.

At the launcher's 1100 × 760 minimum, avoid four narrow columns. Use a purpose-group menu instead of the 160-point group rail when the editor would have less than 480 points; present the 280-point Binds inspector as a sheet when it would leave insufficient keyboard width. Let toolbars wrap into a second row. Scroll content, keep navigation and sheet footers reachable, and never shrink controls or body text to fit. These are implementation adaptations of the large fixed-width boards.

## Shared primitives and materials

`Theme.swift` owns all appearance colors, including new `control` (native toggles/sliders), `caution` (watch status) and `compare` (comparison markers). `ConfigStudioStyle.swift` supplies metrics, typography, semantic status labels, inline banners, setting labels, comparison readouts and keycap labels. Use existing `ContentPanel(radius: 20, padding: 20 on all sides)` for opaque groups; do not build a competing panel system. Action controls use existing `glassAction`, `prominentAction`, `actionControlSize` and `GlassContainer`.

Glass belongs to navigation, toolbars and native sheets/popovers. Do not add a custom glass surface inside an already glass-backed native presentation. Content and code wells remain opaque. New views inherit `palette` from `LauncherRoot`, and native value controls use `palette.control`; do not tint a complete page. One prominent action per immediate context; secondary actions stay neutral. Native `Toggle`, `Slider`, `Picker`, `TextField`, `Button`, `List` and menus own interaction, focus and accessibility.

Dark/light colors and key roles follow Design Rules. SF Pro carries prose and controls (14-point rows, 12-point help); stencil is only uppercase titles (46-point loadout, 60-point Players), eyebrows and numerals. Courier is for timestamps, filenames and Expert console names. Numbers use tabular figures. Truncate a key's tiny action caption only when its full action remains available in its accessible label and inspector. Never truncate errors, explanations or import consequences.

The minimum supported system is macOS 26. Release builds use `COD2_LIQUID_GLASS` to select native glass; the material path remains available for explicit fallback captures and accessibility verification. Reduce Transparency removes the custom surface's material entirely and uses opaque `panel`; fallback buttons do likewise. Native glass buttons retain the system's accessibility adaptation. Increase Contrast strengthens the shared palette. Motion must use the environment's Reduce Motion value: no spring, slide or scale when enabled. Status uses a symbol and words in addition to color. `StudioKeyCap` is a label to place inside a native button, not its own input handler.

## Commit boundaries and state ownership

Normal control edits save as people use them. A switch/picker commits one complete transaction; a slider previews during drag and commits on editing end; a numeric/text field commits after valid Return/focus completion. Do not snapshot every keystroke or slider tick. Escape reverts a pending field edit. A failed save keeps the draft visible with a persistent error and Retry/Revert; never display “Saved” before the store confirms the write. Import, Check-up, restore and freeform text are explicit batch transactions with a single undo boundary.

While any game process owns the config, disable mutation actions, active-profile switching and capture. Continue viewing, searching, comparisons and watching saved game changes. Banner copy: “Configs are read-only while Call of Duty 2 is running. Changes you make in game appear here as the game saves them.” The engine spec's live watcher wins over the board's stale “when it closes” sentence. Close the capture monitor immediately if the game starts or the app loses focus. A draft invalidated by an external file change must be reconciled or reloaded before write; never overwrite it silently.

Engineering supplies the following interface responsibilities. These are contracts, not additional duplicate model types:

- **Profile/store:** stable loadout IDs, selected and active IDs, source revision, capabilities/read-only reason, provenance, watched bytes, pending transaction, commit/undo result, and history. Views issue intents; the store atomically snapshots and writes config plus approved chain metadata with revision checking.
- **Catalog/control descriptor:** stable setting ID, group, plain title/help, optional Expert details, typed current/default value, valid choices/range/step/units, flags, variant, read-only/server-owned reason and sources. Explicitly represent dynamic/unknown data. Cheat-protected FOV never appears as a loadout control.
- **Rules/compare:** status and plain reason, confidence/source, legal values, server ownership; comparison source ID and each candidate value. “Changed” means different from the variant default; History diff compares revisions. Locks and notes are metadata, enforced in the write layer as well as the UI.
- **Input service:** device identity, physical key → game key → displayed label mapping, availability/reason, role/action, capture state, conflict result and measured polling-rate timestamp. Capture only uses a local event monitor, consumes captured events so they cannot activate controls, and removes the monitor on every exit path. Escape always cancels; assigning Escape needs an explicit key-picker action.
- **Import session:** source identity/provenance/signature status, destination ID or new-loadout proposal, parsed changes, dependency results, classifications, selections, blocked reasons, platform translations, validation and apply outcome. Include transitive executable commands in review, even after apparent comments; UI cannot classify by line appearance.
- **Advice/history:** summaries with actual timestamps and available fields, suggestions with exact proposed changes/evidence/source, and snapshots/diffs/restore outcomes. No suggestion invents hardware limits, DPI, measurement windows or permission claims.

## Safety, uncertainty and keyboard completion

Confirmed decisions: launcher-owned chain files and Windows-profile import. Network defaults remain unchanged pending upstream verification. Rule values come from verified catalog/ruleset data, never from the canvas. Imported `seta` chains stay intact; export conversion is explicit. Match-summary copy describes only schema fields actually recorded; the canvas's mention of “hits” is not supported by the current spec. A signature validates the catalog's origin/integrity, not the contents' safety.

New shortcuts: Command-1 Deploy, Command-4 Configs; preserve Command-2 Servers, Command-3 Library and Command-comma Settings. Command-F focuses the current page search, Command-K jumps to a setting in Configs, Command-O starts file import, Shift-Command-V starts paste review, and Command-Z undoes the focused editor transaction. Prefer `UndoManager`/focused commands so ordinary text undo still works. Native sheets own Escape and the default action; Return must not submit an import while editing multiline text.

VoiceOver receives name, value, state and consequence. Icon-only actions name the setting (“Reset Mouse speed to default, 5.0”). Keycaps announce key and action, with unavailable explanation; inspector actions retain focus after commits. Group titles have header traits. Compare markers speak value and source. Status changes are announced once after successful mutation using the appropriate native accessibility notification, not a repeatedly updating live region. All rows remain operable by keyboard with visible focus and at least 28-point practical hit areas. Read-only explanations remain readable at full contrast.

## Integration and acceptance

Add `ConfigStudioStyle` to the launcher's explicit view source list. Engineering owns `LauncherPage.configs`, sidebar routing and shortcuts in Model/RootView/Main; the Config Studio store and views; moving personal controls from Settings; launch-profile selection, migration and chain execution; ready-check integration in Servers; and bundling the real catalog. No fake functional screen or sample directory entry is an acceptable substitute.

For each delivered screen, capture light/dark, standard/increased contrast, normal/Reduce Transparency, native glass/fallback, and empty/loading/error/read-only states. Inspect at 1100 × 760 and a larger window. Test long real names, keyboard-only navigation, VoiceOver, changed input layouts, Reduce Motion and unavailable measurement/rule data. Verify each mutate action against store tests for locks, process ownership, external revision conflicts, failed writes and undo. Component typechecks and offscreen rendering are useful evidence but do not satisfy the full screen accessibility audit.

Apple primary guidance checked 7 October 2026: [Materials](https://developer.apple.com/design/human-interface-guidelines/materials), [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), [Reduce Transparency](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducetransparency). SDK typechecks validate the existing `glassEffect`, `GlassEffectContainer` and glass button availability paths; no new unverified Apple API is introduced.
