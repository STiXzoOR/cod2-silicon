# F2 lighting reconciliation — 2026-10-24

Base: `314d0e6`. Branch: `decomp/f2-renderer-lights`.

## Behavior changed

`R_RegisterLightDef` now retries `light_dynamic` when a requested definition
cannot load, reuses an already registered fallback, and immediately reports a
fatal error when that fallback itself is unavailable. The reconstructed code
instead retried `default`, including after failing to load `light_dynamic`.
The full-definition-list header now matches the original `Loaded light defs:`;
the reconstructed header had an unsupplied `%i` conversion.

These changes are native-only. Existing native layouts, case-insensitive cache
lookup, successful insertion, initialization and shutdown remain unchanged.

Mac 1.3 authority: `R_RegisterLightDef` at `0xedb98`. The failure path compares
and retries the literal at `0x250e48`, which is `light_dynamic`; the equality
branch calls the fatal-error path at `0xedc31`. The capacity branch at `0xedc50`
uses the literal at `0x250df4`, `Loaded light defs:\n`, with no variadic argument.
`R_InitLightDefs` at `0xedcf4` uses the same fallback literal and stores its
result; `R_ShutdownLightDefs` at `0xedd14` only clears the count.

## Selection and surface comparison

The inlined selection and surface loops in `R_GetPointLightPartitions`
(`0xedd24`) were compared with the native helpers. For ordered finite scores,
they agree on radius-squared versus distance-squared cross-products, strict
ranking, equal-score handling, pivot exchange and prefix/suffix reduction.
The original restarts its backwards scan after a swap; the native helper retains
the already classified suffix. A private algorithm-model comparison checked
21,324 finite rank/tie sequences of lengths one through seven and every smaller
wanted count; full resulting order agreed. This is supporting model evidence,
not execution of the original binary.

Both paths collect unculled lights in scene order, use the minimum of the dvar
and caller partition limits, visit surfaces backwards, skip missing bounds,
include equality at the light radius, copy each included surface, increment
both scene and backend surface counts, and retain only nonempty partitions.
The public output remains the light pointer, first surface and count.
`r_dlightLimit` is registered from 0 through 32; the normal scene caller uses a
256-partition limit and skips this call when dynamic lights are disabled.

## Proof-first tests

Existing renderer fixtures inspected: `lighting_lookup.c`, `static_lighting.c`,
`commands.c`, and the focused runner pattern in `run_sun.py`. They do not exercise
light-definition registration. No coverage-only selection fixture was added.

Added `tests/lp64/renderer/lights.c` and `run_lights.py`. The runner compiles the
actual production source with the engine compile database's native stock or
CoD2x flags, assertions enabled, AddressSanitizer and UndefinedBehaviorSanitizer.

## Preservation and limits

`unifdef -UCOD2_X64` on the baseline and changed `r_light.c`, followed by `cmp`,
is byte-identical (both unifdef statuses checked as 0/1; cmp exits 0).
`git diff --check` passes. No shared headers, reference sources or assets changed.

No original executable replay, capture parity, full native builds or live game
runs were performed in this worker. Root owns integrated validation. Linux
object comparison is unavailable; OFF source equality is not that gate.

Unordered floating-point edge behavior is not closed: original SSE comparisons
can take the selection branch or include a surface when an operand is NaN,
where the current C ordered comparisons do not. Ordinary finite cases match;
this unit did not establish an ordinary gameplay trigger for unordered operands.
No NaN guard, normalization or alternative selection policy was added.
The original capacity fatal-error call also appears to provide fewer variadic
arguments than its format requires; the existing native explicit name/count
arguments were retained rather than introducing undefined behavior.

Considered and not built: additional coverage-only tests for unchanged
selection/surface paths, a new count guard, and a fallback hierarchy. None is
needed for the confirmed registration defects or required by the original.
