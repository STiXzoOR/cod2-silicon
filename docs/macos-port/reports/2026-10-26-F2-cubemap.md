# F2 cubemap capture and lighting

Native cubemap capture now keeps six independent face buffers, reads a full
square for each face, and supplies BGR pixels and the original face directions
to TGA serialization and diffuse lighting. The original single-int placeholder
could not hold even one native pointer; a normal capture overwrote global state.

## Recovered Mac behavior

All production changes are guarded by `COD2_X64` in `r_screenshot.c`.

- Mac STABS describes `cubeShotGlob` at `0x00d51c00` as a 24-byte structure
  containing six i386 pixel pointers. `R_EndCubemapShot` stores at
  `0x000e8b5d`, indexed by face minus one. Native storage is now six native
  pointers instead of a four-byte `int` treated as a pointer array.
- `R_EndCubemapShot` at `0x000e8b69`–`0x000e8b88` passes the resolution as
  both width and height. The reconstruction instead passed pixel border as
  height, normally reading one row. Native now reads `res × res`.
- Original readback supplies BGR while native platform readback supplies RGB.
  The four-byte cubemap capture is converted to BGRA before the existing row
  reversal and gamma callback. Save and Lighting therefore receive their
  original channel convention. Save replaces alpha with Fresnel reflectance.
- The seven basis entries at Mac `0x0032afe0` contain the unused zero entry
  followed by up, down, front, back, right, and left face bases. The native
  placeholder was entirely zero. The restored cardinal bases provide the
  directions used by Save's Fresnel alpha and Lighting's hemisphere sampling.
- Lighting's `pow` exponents are promoted float constants. Mac instructions
  at `0x000e96d3`–`0x000e96db` pass double bits `0x40019999a0000000`
  (`(double)2.2f`); `0x000e9b58`–`0x000e9b60` pass
  `0x3fdd1745c0000000` (`(double)0.45454545f`). Native now uses those values
  instead of double literals `2.2` and `0.454545`.

The End, Save, and Lighting bodies were compared with the private Mac
instruction export and fresh `otool` output. STABS establishes storage shape;
original numeric constants establish the face convention. No disassembly,
reference source, game images, or assets were copied into this repository.

`CL_CubemapShot_f` is reachable through the registered in-map `cubemapShot`
command. Its normal loop captures faces 1–6 before optional lighting and six
Save calls. The production fixture executes those renderer calls in that order.
It does not replace them with a test implementation of capture or lighting.

## Native safety adaptations

The original assumes valid caller indices and successful captures. Native now
rejects face indices outside 1–6, frees a prior live face on replacement, and
clears ownership after Save. A failed readback frees its allocation, resets
the render target, and leaves no face to serialize. Save skips missing faces;
Lighting frees and clears every captured face when the set is incomplete, so
the command cannot subsequently save raw captures under lighting filenames. These prevent use of stale/uninitialized
pixels and double frees. They are intentional native safety behavior, not
claims of equivalence to the original on invalid calls or failed GL reads.

## Preserved behavior and remaining module scope

Original readback ignores its x/y border arguments and reads from x=0 and
screen-height minus requested height. That crop quirk remains. End's row
reversal, TGA bottom-origin descriptor, Fresnel alpha, and gamma-call condition
remain unchanged. Native four-channel readback retains its initialized alpha;
Save overwrites it and Lighting explicitly sets alpha to 255.

The earlier ordinary screenshot and resampler reports cover those paths.
This unit repairs cubemap storage and color consumers, but does not claim
whole-module parity or usable world cubemaps from the original command. The broader
module comparison still notes the native before-present screenshot queue and
front/back-buffer fallback as platform adaptations; the legacy card-type-1 GL
disable branch differs but native `MacDisplay_GetCardType` returns zero.
`savegame` accepts extra arguments natively where the Mac checks exactly three;
that command-dispatch edge remains outside this cubemap batch. Original
levelshot orientation and header-placement quirks remain documented separately.

## Integration findings and live checks

The completed independent review found that returning early from incomplete
lighting left successful raw captures available to Save. The correction frees
and clears all faces. Its strengthened fixture failed before the correction
and passes afterward; subsequent Save calls write no files. Existing files are
not deleted. Lighting coverage still uses identical colors on all six faces,
so it does not independently prove face-to-buffer hemisphere indexing.

A linked stock run then crashed in Begin before its device call. This file
had declared `dx` as a pointer although generated renderer state is an object;
its first bytes became the invalid pointer `0x3000`. The original fixture had
accidentally reproduced that incorrect pointer declaration. Native code now
uses the existing `imp_dx` object import, and the fixture supplies object
storage. The legacy declaration is unchanged. Both full client/dedicated
Release builds and all 11 cubemap sanitizer groups pass with this correction.
The earlier failed driver using a Python without Pillow and the subsequent
engine crash are retained separately in private evidence.

Stock and CoD2x live commands each produced six 128-square reflection TGAs and
six 16-square lighting TGAs, with complete payloads and clean process exits.
A JPEG after capture visibly shows normal Toujane rendering. The VM was
suspended during each native run and restored afterward; each run used a
private home and the exclusive game lease.

**The reflection images are solid magenta, not world captures.** Mac
`CL_CubemapShot_f` writes zero to the fifth argument at `0x00172b62` and calls
`CG_DrawActiveFrame` at `0x00172b9d`. That callee stores the argument in
`renderScreen` at `0x001d4a8d`–`0x001d4a90`, tests it at
`0x001d4ae7`–`0x001d4aec`, and returns zero at `0x001d4e6a`–`0x001d4e79`
before world drawing. An independent read checked the original instruction bytes and snapshot
side effects; no snapshot write re-enables `renderScreen`. Native code has
the same call and gate. Begin's magenta
clear therefore remains. This command behavior is preserved; no original Mac
runtime capture was available to compare. The live run establishes command
execution, output shape and subsequent rendering, not useful cubemap imagery
or visual parity. Synthetic production-function fixtures establish the
readback, channel conversion, Fresnel and lighting arithmetic separately.

The follow-up also found a separate missing cubemap timing branch in native
`CG_ProcessSnapshots`; it does not re-enable drawing and is outside this
screenshot-storage repair. It remains a source-comparison follow-up.
