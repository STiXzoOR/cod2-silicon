# F1 mover collision and trigger hint corrections

Three native-only corrections in `g_mover_mp.c`, based on `bd18d2f`:

- Push-position traces retain an entity's nonzero clipmask; only zero uses
  default `0x811`. Previously every trace used the default.
- The corpse shortcut checks contents `0x04000000`, rather than unrelated
  bit `0x4`. This keeps corpses from blocking movers without exempting other
  entities. As in Mac, the shortcut applies only with a nonzero clipmask.
- Spawned use triggers recognize `HINT_INHERIT`, setting hint type to -1.
  The previous `HINT_NOICON` spelling rejected the real inherited-hint token.

Mac authority: `__Z18G_TryPushingEntityP9gentity_sS0_PfS1_` loads clipmask at
`0x1ba7dd`, branches on nonzero at `0x1ba7e5`, selects the zero default at
`0x1ba7eb`, and passes the retained mask at `0x1ba7f9`. The corpse tests at
`0x1bab22`, `0x1baa97` and `0x1bad1d` test bit4 in the highest contents byte,
meaning `0x04000000`. `__Z18trigger_use_sharedP9gentity_s`, `0x1ba585–0x1ba5cc`,
compares the independently inspected string at `0x2de848` (`HINT_INHERIT`) and
sets hint type -1. Linux 1.3 agrees; its code was read only, never copied.

`tests/lp64/game/f1_mover.c/.py` exercises the actual pushing entry point,
production angle math and case-insensitive string comparison. It crosses
zero/custom clipmask with ordinary/bit4/corpse contents and entity/missile
owner exclusion; checks movement and push bookkeeping; and initializes
inherited and ordinary health hints. Before engine edits, mask/corpse cases
failed assertions and the valid inherited hint reached a null-string read
under UBSan. After edits, both stock and CoD2x pass ASan/UBSan with assertions
and nonrecovering sanitizer checks.

The initial fixture also proposed an unknown `HINT_NOICON` case. Inspection
confirmed the original Mac table has a null sixth entry and its loop/string
comparison does not tolerate unknown hints. That invalid-input case was
removed before the fix; no new arbitrary-hint behavior is claimed. The valid
`HINT_INHERIT` failure remained the observed pre-fix regression. No unrelated
string-comparison or invalid-input behavior was changed.

The engine source is byte-identical to baseline with `COD2_X64` undefined;
whitespace checks pass. Linux object/binary verification remains unavailable.
This bounded unit does not reconcile all mover jitter/rollback behavior.
