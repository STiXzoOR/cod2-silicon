# R3 initializer replacement proof

The parent accepted an unapplied, exact replacement proposal for one original
Mac multiplayer initializer. It would create 76 instruction records covering
237 bytes, replace three conflicting full records covering six bytes, and
classify 231 currently unknown bytes. The accepted generation 11 project remains
unchanged at 11,826 unknown bytes.

Original STABS and FDE records agree on the 721-byte extent. Two independent
decoders agree on its 212 instructions and on the three alternate old starts.
The complete old instruction metadata is a replacement precondition.
The proposed body extension retains its existing owner and requires all 8,115
function identities, 4,621 original region identities and existing references
to survive any later application.

Six incoming DATA references into the conflict have an independently confirmed
enum-argument role. Original argument stores, raw import linkage and the pinned
OpenGL SDK header agree; all six full records remain preserved. The other 166
incoming DATA records also remain, without claiming their roles are resolved.
Two original wrapper tail jumps retain their existing call-and-return analysis
overrides and full metadata.

The proposal requires 23 direct-control reference postconditions and one
conditional local no-return call annotation. It proposes no exception
references, unwind metadata, global noreturn flags, defined-data removal or
operations on the other initializer. Original ordered exception-table rows
qualify cleanup roots; they do not prove actual exception delivery.

The parent replay passed 144 finite original-instruction initializer cases,
18 GL argument cases and eight semantic corruption tests. The initializer trace
union covers all 212 original instructions. Explicit models supply import
effects, reference counts, GL outputs and hypothetical exception transfers.
Neither library/driver execution nor whole-function or native equivalence is
established by those cases.

Fresh regeneration matched 44 evidence files, rechecked 88 consumed inputs and
bound 11 generation 11 metadata files to its accepted manifest. The parent also
verified 283 frozen files, independently checked the exact byte partition and
trace union, and matched the six enum routes to its prior diagnostic.
