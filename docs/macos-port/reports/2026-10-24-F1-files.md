# F1 filesystem lookup and IWD seeks

`FS_ShortOSFilePath` now checks the selected search directory's base path and
game directory separately. Previously it used the game directory as the base
and the global game directory as the second component, so an existing file
outside the working directory was missed. The returned `gamedir/filename`
string and language filtering remain unchanged.

Mac 1.3 `FS_ShortOSFilePath` (`0x33398`) loads the directory pointer into EAX
at `0x333d2` and its game-directory member into EDX at `0x333d9–0x333ed` before
calling `FS_BuildOSPath_Internal` at `0x333ef`. The native change restores those
arguments. The Windows sound streaming caller uses this lookup; this focused
test does not claim an audible improvement in the replacement macOS audio
backend.

`FS_Seek` now returns `-1` when its general IWD seek path has no bytes to skip.
This includes seeking to the current absolute position or current end-relative
position and rewinding exactly to zero through a negative relative seek.
The explicit `SET(0)` and `CUR(0)` fast paths still succeed. Mac `FS_Seek`
(`0x32e8e`) calls the zip reader at `0x32f63`, tests its return at `0x32f68`,
and returns `-1` for zero at `0x3303a`. The reader's zero-length path
(`0x2702c–0x27031`, `0x27169`) returns zero without touching the buffer.

The existing native scratch-buffer adapter stays intact. The Mac passes a
null output buffer on its general seek path, which its zip reader does not
support for positive stored reads; the deflated path delegates that buffer to
inflate. This work does not reproduce that defect or infer ordinary positive
seek behavior from it. No bundled zip code was changed.

## Verification

`tests/platform/run_files.py` compiles the actual filesystem translation unit
and existing zip reader with stock or CoD2x engine flags, assertions and
ASan/UBSan. It creates only synthetic temporary files and archives:

- The loose file lives under a search path whose game directory differs from
  the global one. Ordinary and matching-language lookups failed before the
  fix; missing-file, wrong-language and ignore-localized controls pass.
- Stored and deflated IWDs each exercise five previously wrong zero-byte seek
  statuses, plus the two successful fast paths, real archive reads, rewind,
  multi-chunk forward seeks, EOF and close/reset.
- Real loose-file reads, short reads at EOF, all three seek origins, file
  position/length and close/reset also pass.

The final fixture against `83aacfb` fails 14 checks (four lookup/close-count
checks and ten archive seek statuses). Both final stock and CoD2x runs pass.
Config redirection and streamed-file adapters are outside these cases.

Run from the checkout, substituting the available engine compile database:

```sh
taskpolicy -b nice -n 19 python3 tests/platform/run_files.py \
  --compile-db /path/to/build-macos/compile_commands.engine.json \
  --output "$HOME/Library/Application Support/CoD2-native-decomp/F1-files.noindex/stock"
# Repeat with build-macos-codx/compile_commands.engine.json.
# Add --baseline 83aacfb to reproduce the 14 failed checks.
```

`unifdef -UCOD2_X64` plus `cmp` matches `com_files.c` at `83aacfb` exactly;
`git diff --check` passes. These checks do not replace the unavailable Linux
object comparison. Private reference notes and red/green logs are in
`~/Library/Application Support/CoD2-native-decomp/F1-files.noindex/`.

## Remaining scope

This is a bounded correction, not completion of the filesystem module.
The examined Mac `FS_Read`, `FS_FCloseFile`, hash, localization and loose-file
seek paths agree with the current reconstruction. The surprising
`.dm_NETWORK_PROTOCOL_VERSION` literal in `FS_PureIgnoresExtension` is present
in the Mac binary and was preserved. Full searchpath/IWD precedence and
CoD2x-specific config behavior remain to be reconciled. Full builds and live
checks remain with integration.
