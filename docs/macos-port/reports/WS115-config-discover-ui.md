# WS115 — Config Studio: Discover, import review and the Servers ready check

2026-10-09. Worktree `config-ui-discover`, branch `codex/config-ui-discover`, based on `codex/config-studio-int` at `defeb5a` (all Config Studio models plus WS103's Configs, Settings and History screens). This unit builds three UI surfaces on the I1/I2 and A3 models: Discover › Players, Saved and a player's detail; the import review sheet and its sources; and the ready check above Deploy in Servers. It adds no engine, Theme or model behaviour change. Evidence: `~/Library/Application Support/CoD2-native-current-readiness/WS115.noindex/` (logs and review renders; nothing from it is committed).

## What was built

**Discover in the Configs column.** Under My Loadouts, a Discover section has Players and Saved (with its real count). Choosing either replaces the loadout detail with the Discover page; choosing a loadout, making one or finishing an import returns to it. While Discover shows, the loadout toolbar (Settings/History, Jump, More) is hidden, because it acts on a loadout that isn't on screen.

**Players.** Stencil eyebrow and 60-point PLAYERS title, a search capsule (Command-F; player, team, role, era, feel or style) and the page's one prominent action, **Add a Config**, a pull-down that opens a real AppKit menu: From a File… (⌘O), From a Link or GitHub…, From This Mac’s Server (localhost)…, From Your Windows Install…, Paste (⇧⌘V). States:

- *Unavailable* (production today): `ConfigDirectory(cacheURL:)` has no trust configuration, so `load()` reports unavailable without touching the network or the cache. The page says “NO PLAYERS YET — Shared setups from players aren’t available yet. Each one needs the player’s permission and a signed catalog entry before it appears here. You can still bring in a config of your own.” with **Add a Config from a File…**. No search field (nothing to search), no footer claims.
- *Loaded* (only from a verified signed index): shelves grouped by the entries' own `era`, in index order; equal-height cards with favorite-map art from the person's game data (existing illustrated fallback), a stencil monogram, name, team · role, the italic feel line and style chips, plus a bookmark glyph when saved. A cached index shows “Showing the copy saved on this Mac” with the refresh error. Empty search: “NO ONE BY THAT NAME”. A failed load: “OUT OF REACH” with Try Again.

**Saved.** Verified bookmarks as cards; a bookmark whose entry left the signed index is listed as “No longer in the directory” with Remove. Production: “NOTHING SAVED … The player directory isn’t available yet, so there’s nothing to save.” with Browse Players.

**Player detail.** Back to Players (⌘[), a 250-point hero (map art under a scrim, monogram, era · role eyebrow, 56-point name, feel), **Try This Setup** (prominent) and a Save/Remove circle. Story panel: the entry's story, Era/Team/Role/Favorite map, “Shared with permission · Source · Credit · Signed catalog entry”, and “Permission from X on DATE. The signature shows this entry came from the catalog unchanged; it doesn’t make a config safe, so you still review every line.” with the permission record link. **What changes for you, compared with** the active loadout: the verified download reviewed against it in memory (nothing written): locked settings always listed (“Your brightness stays 1.4 — They use 1.5, but you locked yours…”), then up to six of the lines Review would tick (“Frame rate cap: 250 fps — Yours is 333 fps.”), turn speed as a ratio (“You’ll turn about 19% slower”) with a centimetres-per-turn claim only when the loadout has a DPI, and binds (“Your binds stay yours — This setup doesn’t include any keys.”). **In this setup**: counts of settings, key bindings, lines needing OK and lines never imported, style chips, and the Windows note.

**Import sheet.** One sheet steps from a source to its review, so a link or Windows profile moves straight on without a dismiss/present race.

- *Link*: one field for https, GitHub blob/raw, gist and http://localhost (prefilled from the localhost menu item), checked with `ConfigImportLoader.permittedURL` before reading; credentials in links are refused.
- *Windows*: bounded `WindowsProfiles` discovery of mounted drives (and folders the person chooses), Profiles first with “In use on Windows”, “Backups (optional)” with their file names, what was searched, unreadable/truncated notes, Choose Folder…. Each profile imports as a new loadout with the `.windows` platform.
- *File* (⌘O, `NSOpenPanel`), *Paste* (⇧⌘V: the clipboard goes straight to review as Latin-1 via `ConfigDocument.encode`, so Return can never submit while editing text) and *Drop* (a file or text dropped anywhere on the Configs page, with a dashed accent target).
- *Review*: header with IMPORT eyebrow, title, **Review / Import Everything**, source chips (Players catalog / File / Link / GitHub / Pasted text / Windows profile, Signed catalog entry, From Windows, credit or file name) and **Into** (New loadout “Name” or any existing loadout; choosing one never changes the active loadout). An existing destination says “This changes Main itself. History keeps the version from before, so you can undo it.” The body groups ticked changes by purpose group (then Key bindings, Other commands) with “3 of 4” counts, then **Protected** (locked, never selectable), **Needs your OK** (unticked by default, exact line always shown), **Choose on this Mac** (display/machine/Windows-only choices, with the model's explanation) and **Never imported** (credentials, paths, protected settings, unknown commands, files that weren't included — redacted exact lines). Plain titles use catalog names and units (“Mouse speed — 2.6 → 2.1”); console lines appear only under Show Details or on risky/blocked rows. Inert names carry a “Has no effect in CoD2” label. Import Everything shows a negative banner naming the concrete consequences and still excludes blocked and locked lines; unticking a line there returns to Review with the rest ticked (board behaviour). The prominent button names the selection (“Apply 7 Changes”, “Import All 10, Including 4 Risky”); with any risky line ticked a confirmation lists the consequences first. Apply is one `ConfigImportSession.apply(to:)` transaction; failure keeps the sheet, the ticks and the loadout's bytes and shows why; success closes the sheet, shows the imported loadout (not made active) and announces it. Importing into an existing loadout registers **Undo Import** (restores the version before as a History transaction, refused if the loadout changed since).

**Servers ready check.** A card sits above Deploy in the server inspector, for the loadout this connection would use:

- *Needs a change* (caution): “Your “Main” loadout needs one change here”, each actionable rule in words (“Frame rate cap is 333 fps in this loadout. This server allows 125–250 fps.”), server-set values in one neutral line (“The server sets your competitive server rules, shadows and 4 other settings while you play here.”; Details lists each), **Fix for This Server Only** (when A3 offers verified fixes) and Details.
- *Server sets values only*: neutral “This server sets some of your settings … Your loadout doesn’t need to change.”
- *Unknown* (secondary, minus glyph): “We don’t know this server’s rules” with general advice and Check Again (re-queries this server). Never a check mark.
- *Matches*: a quiet “Matches this server’s listed rules” row; Details adds “Your saved settings match the rules listed for Public CoD2x 1.4.6.8. Only those settings are checked.”
- *Unavailable* (no Configs session): “We can’t check this server”.
- **Loadout for this game**: a native pop-up of every loadout; choosing another calls `useLoadoutForServer` (never `selectProfile`), shows “Using your “Scrim” loadout for this game. Main stays as it is.” with Undo, re-reviews that loadout, and Deploy reads “Deploy with Scrim”.
- **Fix for This Server Only** asks first: “While you play on <server>, the game uses Frame rate cap 250 fps instead of 333 fps. Your “Main” loadout doesn’t change. Anything you change in the game during this connection is discarded when you leave.” The staged state repeats the disclosure (WS109 requirement) with Undo.
- Details lists the cited rules with console names, values, status, sources, the report's limitations and the advertised facts.

## Model and shared-file changes (all additive)

- New: `launcher/ConfigDiscoverModel.swift` (Discover/import view store, plain row presentation, player comparison), `ConfigDiscoverView.swift`, `ConfigImportView.swift`, `ServerReadyCheck.swift` (ready-check presentation and card store), `ServerReadyCheckView.swift`.
- `ConfigsView.swift`: ConfigsShell takes the discover store, shows Discover in place of the loadout detail, hides loadout toolbar items while it shows, hosts the import sheet and drop target (`.configImportFlows`); LoadoutColumn gets the Discover section and doesn't highlight a loadout while Discover shows.
- `Model.swift`: `let discover` (production directory: `ConfigDirectory(cacheURL: home/directory/index.json)`, no configuration), notices routed to the launcher banner, preview cases for the new harness screens, and `readySession` (`studio.session ?? configStudio`) for `readyCheck`, `useLoadoutForServer` and `fixForServerOnly`. In the app both are the same session; the harness and tests attach one to a preview model. `play()` is unchanged.
- `ServersView.swift`: the card above the password field and Deploy; Deploy's title from the card.
- `Main.swift`: File menu “Import a Config…” (⌘O) and “Review Pasted Config” (⇧⌘V), which open Configs and start the review.
- `scripts/build-launcher.sh`, `tests/launcher/run.sh`: the five new files in the launcher, harness and macOS 13 typecheck lists; the harness also builds `tests/launcher/DirectoryFixture.swift`; `run.sh` runs the new `config_discover.sh`.
- `tests/launcher/Snapshots.swift`/`snapshots.py`: eight new Config Studio screens, sheet captures (`-sheet.png`, `-sheet@2x.png`), two new `--actions` flows.

## Decisions (with reasons)

| Board / brief | This build | Why |
| --- | --- | --- |
| Featured hero “FEATURED · [ACHIEVEMENT]” | No featured hero | The signed schema has no featured flag or achievement; picking one would invent curation (contract: no fabricated featured player or achievement). |
| Curated shelves (“Built for the 333 jump”) | Shelves by each entry's `era` | Only real metadata; no placeholder shelf. |
| “Close to your setup / Quite different” on cards | Not shown | It needs every config downloaded and is a similarity claim the contract forbids; the detail page compares exactly instead. |
| Footer “Also on GitHub as cod2-configs” | Omitted | The repository isn't published (WS108). A loaded directory says every setup is shared with permission and still reviewed. |
| “Notable settings, explained” | “In this setup” counts and style chips | The schema has no per-setting “why” text; counts come from the actual review. |
| Compare (opens Expert with the player) | Not offered | WS103's Expert compares the person's own loadouts only; a player source needs a ConfigStudioModel change (left for later). “What changes for you” covers the comparison here. |
| Separate “Import…” button | One **Try This Setup** | The review's Into picker already chooses an existing loadout. |
| Outcome titles (“Your jumps follow 250 fps physics”) | Catalog names and values (“Frame rate cap: 250 fps”) | Outcome copy per setting isn't authored (as WS103 found); turn speed is derived from real values. |
| “Add a config” as an HTML menu | Prominent button opening an `NSMenu` | SwiftUI `Menu` can't take the prominent style on macOS 13; a real menu keeps native keyboard, VoiceOver and appearance. |
| From a link… / From GitHub… / localhost… | One link step; two menu items (localhost prefilled) | The I1 loader handles all three from one URL; separate GitHub item would open the same field. |
| “Use “Scrim” loadout” | “Loadout for this game” pop-up of all loadouts | Nothing establishes which loadout is “most careful”; the person chooses. |
| “Ready. No special rules here.” | Scoped “Matches this server’s listed rules” | A3: a match covers only the cited saved-value rules. Unknown never reads as ready. |
| Import new-loadout ID `Import-<UUID>` (I2 default) | WS103's folder name from the display name | The game's own profile menu shows the folder (WS103 decision). |
| Sheet geometry | System sheet (glass on macOS 26) | Glass never stacks on glass; content groups are opaque panels. |

Copy gaps for the catalog owner: per-setting outcome sentences for import rows and the player comparison; plain names for helper/unknown settings (shown as “A helper setting the config creates” with the exact line); a meaning for the directory `platform: native` value (shown without a line); Windows driver/display notes are model copy.

## Verification

All compiles and tests ran under `taskpolicy -b nice -n 19`, with `TMPDIR` inside the evidence directory and at most two compile jobs at once. The Mac was shared with other agents (load average above 20), so builds took 4–12 minutes each.

```sh
evidence="$HOME/Library/Application Support/CoD2-native-current-readiness/WS115.noindex"
TMPDIR="$evidence/scratch" sh tests/launcher/config_discover.sh            # new: 5 groups, PASS
TMPDIR="$evidence/scratch" COD2_LAUNCHER_TEST_OUTPUT="$evidence/suite" \
  taskpolicy -b nice -n 19 sh tests/launcher/run.sh                         # exit 0, 78 PASS lines (logs/suite-final.log)
bash scripts/build-launcher.sh "$evidence/build-app"                        # SDK 27.0, minos 13.0, system frameworks only: exit 0
"$evidence/suite/snapshot-harness/LauncherSnapshots" "$evidence/shots/actions" --actions   # also run by snapshots.py: 5 real-click checks, PASS
git diff --check defeb5a HEAD                                               # clean
```

**Focused tests (`config_discover.sh`, new).** It compiles every launcher source except `Main.swift` with Swift 6, complete strict concurrency, warnings as errors and macOS 13, plus `DirectoryFixture.swift` and `ConfigDiscoverTests.swift`, and drives the same calls the sheet and the card make against private temporary homes:

1. A pasted Windows-style config opens a review into a new loadout: plain rows (“Mouse speed — Set to 2.1”), no console names in change titles, connect/name/unbindall/inert lines needing an OK and unticked, the password blocked and redacted, `exec` never imported, `r_mode` kept on this Mac, the button naming the selection; Import Everything ticks every eligible line and names the risky count; unticking there returns to Review with the rest ticked. Apply writes exactly `preview()`’s bytes to `Pasted_config`, only the ticked lines, one `.import` History row; Main and `active.txt` are unchanged; a second apply is refused; the imported loadout is shown without becoming active.
2. Into Main (brightness locked): the lock is a Protected row (“Brightness stays 1.4”), changes read “2.6 → 2.1”; Main holds exactly the reviewed bytes, brightness still 1.4; **Undo Import** restores the exact prior bytes as a `.restore` transaction.
3. A loadout changed after review: Apply refuses, the sheet says why, bytes and History count unchanged. While the game runs: refused, nothing created.
4. Production `ConfigDirectory(cacheURL:)`: unavailable, no entries, no Saved, no cache file written. Signed fixture: shelves by era, search by role, Saved, the player comparison against Main (lock acknowledged, “You’ll turn about 19% slower” without a DPI claim, risky and blocked counts), nothing written; Try This Setup reviews a signed Windows entry into a new loadout; closing writes nothing.
5. Ready check on a preview `LauncherModel` with a temporary session: a fresh competitive CoD2x server gives “Your “Main” loadout needs one change here”, the fix in words (“Frame rate cap 250 fps instead of 333 fps”), server-set values neutral, no console names; **Fix** stages `com_maxfps=250` with Main's config, sidecar, `active.txt`, History and the profile folder list byte-for-byte unchanged; choosing Scrim for this connection changes nothing on disk and Deploy reads “Deploy with Scrim”; Undo clears it; an unobserved server is unknown (never positive, no fix); a public server with Pub matches with scoped wording; no session reads as unavailable.

**Full suite** (`logs/suite-final.log`, final tree, 33 minutes, exit 0): Core, real local UDP, artwork, F1, F2 (15 cases), F3a launch, the Config Studio model, catalog (733 settings, 235 commands), I1 import, I2 import session, directory and its tools, rules, Check-up, bindings, ready check, input devices, chains (ASan/UBSan), the new Discover runner, fonts, the Theme-only button-style check and the Swift 6 / macOS 13 material-branch typecheck of all 41 files pass. The snapshot stage rendered 58 window captures (27 screens dark and light, plus the two import sheets) with **348 shapes and 0 findings**, passed every dark ≠ light and size check, the material fallback (48 + 2 shapes, 0 findings), Increase Contrast and Reduce Transparency for all 14 Config Studio screens (154 shapes each, 0 findings), and the five real-click actions. Because the session was unlocked, this is the first run in this series where the existing `dark != light` gate passed instead of failing on blank captures. An earlier full run (`logs/suite.log`) stopped at one new assertion: under Reduce Transparency, the window behind the import sheet in light appearance was byte-identical to the standard capture, because nothing in that window is translucent and the sheet's material belongs to the system. `snapshots.py` now skips only that Reduce Transparency equality check for the two sheet screens; every other assertion is unchanged.

**Review harness actions** (real clicks in the window, temporary home): the two WS103 checks, plus clicking the review sheet's **Apply** imports exactly the ticked lines into a new loadout as one Import transaction with Main and the active loadout unchanged; clicking **Fix for This Server Only**, then its confirmation, stages `com_maxfps 250` with Main's config, sidecar and active selection unchanged; clicking **Undo** clears it. ## Composition

Compose on `codex/config-studio-int` after `defeb5a`: `458e26c` (Discover and import), `4255264` (ready check), `09de192` (tests and harness), then this report's commit. Each carries DCO sign-off and the requested author email. Shared files were changed additively: `ConfigsView.swift` (ConfigsShell/LoadoutColumn only; `ConfigStudioTab` untouched), `Model.swift` (one property, two init lines, `readySession`, preview cases), `ServersView.swift` (two lines), `Main.swift` (two menu items), and one line each in the build and typecheck lists. The intermediate commits were not built on their own; the tip was.

No push, tag, remote change or merge. No `.app` bundle was built or registered with LaunchServices (the app build is the bare `CoD2Launcher` executable). Nothing was written to `~/Library/Application Support/CoD2 Silicon/`; no game ran; the user's Windows volume and private corpus were not read. Logs and review renders (synthetic placeholder data only) stay under `WS115.noindex`. The session's safety hook blocks recursive deletes outside the worktree, so its build outputs remain for the orchestrator or user to remove: `build-app/`, `build-base/`, `build-harness/`, `suite/` (binaries and objects; `suite/snapshots/` holds the suite's renders) and `scratch/` (an interrupted compile's temporary objects), about 190 MB. Nothing in the repository is left uncommitted.
