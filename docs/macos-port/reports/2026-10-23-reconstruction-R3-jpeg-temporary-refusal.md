# R3 JPEG temporary-recovery refusal: rejected

Disabling the two added guarded-memory recognition paths during temporary
jump-table recovery prevents four measured incomplete tables, but also loses
the original JPEG six-slot table and both required synthetic no-write positives.
The bounded hypothesis is rejected. No candidate was installed or adopted, and
native production code and the accepted reconstruction generation are unchanged.

## Characterization before the change

The worker built all 94 decompiler objects afresh from the previously corrected
baseline. Its 15 retained fixture results and six memory fixture results matched
the prior stdout, stderr and XML artifacts. Nine switch contracts, 52 upstream
assertions, seven helper cases and 200 freshly executed synthetic i386 paths
provided the baseline checks. Historical malformed full XML documents and two
unadapted parser failures remain explicitly qualified; parsing a table fragment
does not establish a valid full document.

Stage traces show all four negatives first installing six addresses in temporary
recovery and transferring those six addresses into final flow. Final model
matching rejects the memory evidence, but label recovery retains a table that
omits a demonstrated reachable target. The finite instruction traces, rather
than only the historical distinguishing case, define the required target sets.

## Candidate and independent reproduction

The candidate adds exactly two temporary-recovery conditions to the added
recognition paths. It preserves the earlier helper correction and the upstream
recognition paths. Seven focused fixtures and their seven instrumented versions
ran. Instrumented and uninstrumented XML agree, including before the change.

All four negative cases become explicitly unresolved with well-formed full XML,
the intended function decompiled, retained raw indirect-branch evidence and an
unresolved-table diagnostic. Missing or invalid output is not counted as refusal.
All three required positives also lose their tables, which is sufficient to
reject this candidate. The full candidate suite and successful-candidate guard
ablations were therefore not run; the experiment was not broadened.

The parent verified the complete sealed worker inventory and source delta,
freshly compiled both jump-table variants, validated and reused the other 93
objects, and executed all 14 baseline/candidate focused runs. Every result's raw
XML matched the corresponding worker output. A separate audit parsed all 14
complete XML documents, derived reachable targets from the instruction traces,
checked the four first-installation/final-transfer traces and confirmed the
three lost positives. This is a targeted reproduction, not another complete
94-object build.

The failed initial dependency-only build attempts, parser failures and classifier
revisions remain private and immutable. No broad native suite was run because
production behavior did not change. This experiment establishes neither general
alias safety nor native/gameplay equivalence. The earlier soundness problem
still needs a solution that preserves valid recovery.
