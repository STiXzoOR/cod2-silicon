# F1 message wire corrections

Baseline `6c6edd0343259966e2697c8ca561fe6d1c2c5cbe` was verified clean in
`decomp-f1-cmtrace`, branch `decomp/f1-msg-wire`. `behavior_changed: true`.

Two native-only corrections in `src/PC/qcommon/msg_mp.c`:

- `MSG_WriteDeltaUsercmdKey` chooses its extended-field mode from changes to
  buttons above bit zero, weapon, offhand index and roll. Timestamp byte/full
  encoding remains independent. Previously normal sub-256ms commands omitted
  changed extended fields; long intervals unnecessarily selected full mode.
  `CL_WritePacket` (`cl_input.c:969`) serializes commands through this function.
- `MSG_ReadString`, `MSG_ReadBigString` and `MSG_ReadStringLine` preserve the
  integer byte-reader result until EOF comparison. Wire byte 255 previously
  became -1 before comparison, prematurely ending strings and leaving their
  remaining bytes for subsequent opcode parsing. Signed-character cleanup is
  retained after EOF handling. This affects client configstrings, reliable
  commands and server reliable client-command/connectionless parsing.

Mac authority, independently interpreted (no reference code copied):
`MSG_WriteDeltaUsercmdKey`, `__Z24MSG_WriteDeltaUsercmdKeyP5msg_tiP9usercmd_sS2_`,
at `0x17641d–0x176423` chooses timestamp encoding. Separately,
`0x1764c3–0x176511` compares extended buttons, packed weapon/offhand and roll
and branches to full mode at `0x17674d`. The reduced mode XORs the key with
serverTime at `0x17654f–0x176555`. Linux 1.3 guide agrees.

`MSG_ReadString` at `0x173811` loads an unsigned byte, then at `0x17381b`
compares its integer value to -1. Only `0x173847` sign-extends for
`I_CleanChar`. The same ordering appears for big strings at
`0x173883–0x173898`, cleanup `0x1738c1`, and line strings at
`0x17390b–0x173946`, cleanup `0x173950`. Linux guide agrees; production
`I_CleanChar` preserves byte 255.
