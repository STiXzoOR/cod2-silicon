## Model cache lifecycle decision

`R_LockSkinnedCache` remains unchanged after joint inspection of its callers and
both native buffer implementations. Mac `0xd0054` always requests DISCARD
(`0x2000`). Its debug-frame path unlocks at `0xc7880` and relocks at `0xc8d3a`;
Aspyr's vertex-buffer lock replaces delayed-free memory for DISCARD
(`0x1ebe7–0x1ec05`). The native GL buffer lock instead returns stable CPU memory,
and the native draw path consumes client arrays. Metal implements real buffer
generations and its DISCARD path clears the CPU shadow at offset zero.

The existing non-discard debug relock preserves already prepared skin data on
Metal. Merely changing the flag to match Mac would erase that data; it would
have no effect in the GL lock. No such change was made. The cache lifecycle is
a platform replacement with different storage semantics, not an established
per-input parity result. Thread contention, buffer pressure and original-runtime
capture parity remain unverified. No new test was added for unchanged code.
