## Proof fixture

`tests/camera/events.c` includes the complete production event translation
unit from a private snapshot. No production function bodies are rewritten.
It links the real `com_math.c`, including `AngleVectors`; sound, camera shake,
effect scheduling, and display endpoints capture their input arguments.
Unrelated event endpoints abort if unexpectedly called. These are synthetic
outputs, so the checks do not establish sound playback, effect rendering, or
camera-shake attenuation parity beyond the dispatch boundary.

The runner compiles the production translation unit using the selected
stock/CoD2x engine compile-command flags, then builds the assertion-enabled
fixture with AddressSanitizer and UndefinedBehaviorSanitizer. It remaps the
compile-command source root to the current checkout and writes all generated
sources, objects, and executables outside the checkout. `--baseline` selects
the historical event body for regression evidence.

The ten case groups cover:

- `perspective`: 100 reload/empty-reload combinations across local and remote
  entities; flags zero, each high first-person bit, both bits, and unrelated
  low bit; and progressively missing aliases. Expected priority comes from a
  literal independent table, including silence when all aliases are absent.
- `local-actions`: both offhand actions for the same ten flag/entity
  combinations, including spectator/no-view flags and remote entities.
- `reload-start`, `reload-end`, `rechamber`: six combinations each of local
  versus remote delivery, player alias availability, ordinary fallback, and
  complete alias absence, with a distinct wrong alias available as a decoy.
- `quake`: four radius values (`0`, `0.5`, `128.25`, `8192`) checked by exact
  float bits, along with duration, intensity, and the entity origin.
- `oriented-fx`: zero and 90-degree roll with a 90-degree yaw, checking actual
  computed forward/up vectors and origin; invalid effect IDs 0, 64, and 255
  remain suppressed.
- `obituary-icons`: reachable MOD 7/8/9/11/12, generic fallback, ordinary
  weapon icons, wide/flipped weapon icons, names, and dimensions.
- `obituary-message`: world-attacker local death, enemy and teammate deaths,
  local attacker, suicide, killer-name publication, and killcam suppression.
- `controls`: zero event and actual `CG_CheckEvents` ring dispatch, event order,
  event-parameter restoration, and prevention of duplicate event playback.

Private evidence is under
`~/Library/Application Support/CoD2-native-decomp/F2-events.noindex/`.
No original runtime or guest command was used for this unit.

## Validation

The baseline `d497f60` fixture fails the nine changed-behavior groups and
passes `controls` in both stock and CoD2x. The repaired fixture passes all ten
case groups in both modes under ASan/UBSan. Both production translation-unit
compiles also pass using the engine's unmodified compile flags.

The existing platform FX fixture initially failed to link because its capture
endpoints omitted `FX_PlayOrientedEffect`. Its wrapper now preserves the
existing origin, effect, forward-vector and mark checks, additionally checking
the default up vector and all three oriented deliveries. The platform FX
suite passes under ASan/UBSan. Both audio-output configurations also pass all
four groups, including 138 footstep event combinations; that fixture includes
the same endpoint definitions.

Both integrated client and dedicated targets build in stock and CoD2x.
Live `mp_toujane` runs fired/reloaded an Enfield and used frag/smoke, but the
subsequent death step disconnected with `Bad item index 6 on entity` in both
configurations. Screenshots confirm the error dialog; process exit zero does
not make these successful death/respawn checks. The dropped-item failure is
being investigated separately. The VM was suspended for native runs and its
running state restored afterward. Logs and captures remain private.

Exact `unifdef -UCOD2_X64` output compares equal with `cmp` against `d497f60`.
This verifies unchanged legacy source text after conditional removal; it is
not a claim of x86 object identity or original-runtime parity. `git diff
--check` passes.
