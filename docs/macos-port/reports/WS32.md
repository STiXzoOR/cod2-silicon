# WS32 — Metal shaders provider

Branch: `port/metal-shaders`, based on WS29 `351fe824`. The provider implements
the frozen ABI 1 without changing `metal_abi.h`, `metal_core.h`,
`metal_backend.h`, `shim_dispatch.h`, any shared engine header or GL renderer
function. The native CMake source list and first-run setup seam are the only
integration edits. Nothing was pushed or published; no remotes, system packages,
sibling worktrees, original binaries or generated data were changed or added.

## Delivered behavior

After WS21 verifies/extracts the player's local 834-payload manifest, native
first-run setup calls `MacMetalShaders_SetupAfterExtraction` through an exported
optional symbol. It translates the player's 208 vertex and 209 fragment programs
locally and uses `MTLDevice newLibraryWithSource`, strict math and MSL 3.0.
Neither the player nor the runtime path needs `xcrun metal`, an offline metallib
or Xcode. Development fixtures need the existing compiler; no package was
installed. The real client exports the setup symbol, verified with:

```sh
xcrun dyld_info -exports build-macos/cod2_macos
```

`shader_provider.mm` installs `MacMetalShaderOps { abiVersion=1, load, prepare }`.
Preparation validates manifest SHA-256, all 417 original source/CTAB pairs and
bounded CTAB records, rejects a manifest changed during preparation, verifies
generated MSL against a fresh translation, compiles and retains all raster
libraries/functions, and atomically publishes a local cache identity. ABI-1
descriptions carry original source and metadata SHA-256, translator revision
`ws32-arb-msl-3`, stage, MSL path, entry and bounded reflection. `Describe`/`Find`
produce borrowed descriptors. `load` checks every field, sidecar kind, reflection
bytes and device identity, then attaches a retained provider-owned payload with
a release callback. It performs ready lookup only. Existing sidecars retain
their libraries safely across a later preparation.

The local namespace hashes sorted identity JSON containing ABI, original
manifest/source/metadata SHA-256, translated MSL SHA-256, entry, translator
revision, fixed-shader revision/source SHA-256, strict compiler options, GPU
registry ID and OS version/build. Setup and provider output paths are restricted
to subdirectories of `~/Library/Application Support`; the standalone setup tool
now enforces the same boundary. `.prepare.lock` prevents competing publishers.
Original extracted inputs remain outside git. No library, archive or translated
original is bundled.

`BeginLoading`/`SealLoading` delimit producer work. Preparation, shader loading
and typed fixed-variant preparation reject calls after sealing. Ready library,
function, description and immutable-register access remain available. No shader
or pipeline factory is invoked by a drawing callback. Shader locals are owned
by each shader sidecar, preserve float bits and have checked register ranges.
`Snapshot` copies a caller-populated stage bank; `SnapshotState` selects the
separate VS/PS bank and resolves every source-reachable ordered ARB state binding
(`state.fog.color`) from the D3D shadow. Unknown automatic state bindings fail.
Submission allocation, residency and retirement remain WS33's responsibility.
The local metadata audit found 2,605 CTAB records and zero nonzero default-value
offsets, so the sidecar's initially zero local bank does not discard CTAB defaults.

The raster translation and original fixed-function implementation are detailed
in [raster evidence](WS32-raster-evidence.md) and
[fixed-function evidence](WS32-fixed-evidence.md). The local declaration packet
is **736 bytes**, declared in `arb_raster.h` and included by `arb_to_msl.h`.
It stays within ABI 1's buffer-0 slot, with constants in buffer 1, allocation
starts in buffers 2..17 and original texture/sampler slots unchanged. Raster
wrappers implement linked perspective varyings, GL window coordinates/depth,
declaration types 0..16, producer-specific color order, derivatives, LOD,
per-slot float sampler bias, post-shader alpha test and KIL. Semantic compute
keeps its original input/constants/output ABI. The fixed set implements the
engine's 22 enabled combiner operations, FVF expansion, transforms/XYZRHW,
fog/alpha, directional lighting/materials, clipping and colored/solid/copy/gamma
entries. Unsupported state fails with a diagnostic.

Default fixed entries are retained during provider preparation. Additional
2D/cube/3D tuples use `PrepareFixed(types[8])` explicitly during loading; ready
`FixedLibrary`, `FixedFunction` and `FixedSourceSHA256` never compile. WS31 must
include the exact tuple, generated source SHA-256 and `fixed-abi1-r1` in its PSO
key. All seven entries in each tested library are retained before sealing.
Gamma specifically pairs `fixed_post_vertex` with `fixed_gamma` to keep the
LUT register bank independent of stage metadata.

Texture-coordinate generation follows the original Mac shim: `0x20000` uses
camera-space vertex position, then the texture matrix; `0x30000` uses camera
reflection. Original `RB_ChangeGenTexCoords` emits `0x20000` at `0xccfc8` for
`genEyeDirCoords`. Its renderer's position-stream branches at `0x1125b` /
`0x19387` are separate from reflection branches at `0x12013` / `0x19393`.
The initial WS32 cube fixture used reflection for the position flag; final
fixtures correct that oracle and add independent GL position-stream/matrix
comparisons. Normal-generation flag `0x10000` is explicitly rejected because
no engine emitter was found. The unmerged fixed revision remains `fixed-abi1-r1`;
the corrected generated source SHA-256 changes both shader namespace and PSO
identity, invalidating the previous derived cache.

## Runtime binary archive contract for WS31

`shader_archive.{h,mm}` provides a loading helper against ABI 1:

1. `Open(device, ApplicationSupportDirectory, namespaceSHA256)` uses the supplied
   transport device, validates the namespace, takes an exclusive namespace lock
   and verifies archive metadata/file SHA-256 before opening `MTL4Archive`.
2. `Render(archive, MTL4RenderPipelineDescriptor)` tries archive lookup, then the
   same-device Metal 4 compiler during loading. It returns an owned (+1) native
   PSO; Objective-C consumes it with `__bridge_transfer`/`CFBridgingRelease`.
3. `Finish` seals factories, includes both existing hits and new misses in an
   atomic replacement, publishes `archive-v1.json` and `render.bin`, and rejects
   later creation. WS31 owns the prepared PSO map and draw-time ready lookup.
4. `Close` releases the helper and namespace lock. It creates no device, queue,
   command buffer or submission.

Metadata schema 1 contains ABI 1, caller namespace, GPU registry ID, OS build,
binary SHA-256, pipeline count and writer kind. Use the provider namespace as
part of a complete WS31 namespace/key; shader identity alone is not a complete
pipeline-state key. A cache is optional acceleration: identity mismatch,
corruption or driver rejection causes a loading-time rebuild.

On this Mac (macOS 27.0.1, Apple M6), the configured Metal 4 dataset serializer
returns `NO` with no NSError or archive file, even for one independent simple
pipeline; descriptor-script serialization succeeds. The helper first attempts
that writer, then harvests equivalent fully specialized traditional descriptors
with runtime `MTLBinaryArchive`. This archive was actually reopened by
`MTLDevice newArchiveWithURL` and used by `MTL4Archive` to return the requested
Metal 4 PSOs. No legacy PSO or transport is created for harvesting. This is
verified interoperability on this Mac, not an assumption that all archive
formats are generally interchangeable.

The fallback supports plain library entries, vertex layouts, samples, alpha
coverage/one, rasterization, amplification/topology/ICB, shader validation, and
all eight color format/blend/write-mask descriptors. It rejects static/binary
linking, attachment remapping, requested Metal 4 reflection and unspecialized
blending, rather than omitting their semantics. CoD2's current entries require
none of those rejected features. Advanced descriptors can use the native
serializer where supported; `Finish` fails if neither writer can represent them.
No compute/mesh/tile archive helper is supplied.

## The 17 GL-invalid originals

All seventeen translate, runtime-compile, link and load. The current GL driver
rejects their original text before execution. The independent original-program
parity gate remains **400/417**, with zero numerical failures among accepted
originals. The additional repaired-reference gate is **17/17**, with zero
absolute/relative difference over its eight deterministic inputs per program.
These are separate claims: a repaired reference is not execution of the rejected
original.

The inspected original Mac upload constructors provide an important negative
fact: neither performs text repair. `COpenGLVertexProgram` at `0x2318c` submits
its supplied bytes via
`glProgramStringARB` at `0x23328`; `COpenGLARBFragmentProgram` at `0x1c34c` submits
them at `0x1c542`. Both save/restore binding and neither checks `glGetError` after
upload. Read-only `nm` / `xcrun llvm-objdump --macho --disassemble` and in-memory
function-boundary inspection verified this. No disassembly dump was added.
The i386 reference cannot run on this arm64 Mac, so historical vendor-driver
acceptance/execution remains unverified; unchanged upload does not prove what
that historical driver produced.

The decisions preserve the mathematical intent of the observed D3D instructions.
The [ARB vertex](https://registry.khronos.org/OpenGL/extensions/ARB/ARB_vertex_program.txt)
and [ARB fragment](https://registry.khronos.org/OpenGL/extensions/ARB/ARB_fragment_program.txt)
instruction sets exclude these D3D spellings. Microsoft's
[NRM](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/nrm---vs)
defines XYZ-length normalization; the observed destination mask is XYZ.
[DP2ADD](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dp2add---ps)
defines the two-component dot product plus a replicate-swizzled scalar third
operand. Undeclared `_abs` operands are explicit absolute-value modifiers, not
new uninitialized temporaries; an actually declared suffix remains a variable.

`check_invalid.py` independently lowers these to legal ARB ABS; MUL/ADD; and
DP3/RSQ/MUL instructions, preserves OPTION ordering and saturation, and refuses
unobserved DP2ADD scalar/mask interpretations. It compares that legal GL program
to MSL translated from the unchanged original. Reference streams and all outputs
remain in Application Support. WS24 already implemented these mathematical
emissions; WS32 verifies and documents their previously unverified decisions.

## What WS33 and the orchestrator can rely on

No ABI-1 header change is proposed. All implemented features fit provider-local
state and the existing explicit prepare/load API. The integration order is:

1. Install providers before constructing engine objects. During each loading
   phase call `MacMetalShaders_BeginLoading`, then `MacMetal_PrepareProviders`
   with the verified extraction cache, translated output and complete WS31
   namespace/dataset. Prepare fixed tuples and PSOs in this phase.
2. At shader creation/loading resolve the known original name/CTAB identity with
   `Find`/`Describe`, then call `MacMetal_LoadShader` on the corresponding shader
   sidecar. The current clear-only core does not automatically perform this
   association. ABI 1's shader table has no generic shim hook; add the loading
   integration seam in integration-owned engine/core code, without a draw-time
   compilation fallback. Command-line game startup also needs this explicit
   loading step; only native application setup currently invokes preparation.
3. Retain ready native functions/libraries in WS31's PSOs. Use the archive helper
   during loading, finish it, publish only ready pipelines, and seal shaders
   before scene readiness. `BeginLoading` is for a real subsequent loading phase,
   never a response to a draw-time cache miss. All provider producer operations
   assume the serialized loading thread.
4. For programmable draws bind the 736-byte raster packet in both stages'
   buffer 0; copy separate stage register snapshots in buffer 1. Bind allocation
   starts in 2..17, normalize declaration usages and producer color order, fill
   framebuffer height, bias and alpha fields, and keep native sampler LOD bias
   zero. Validate ranges before encoding and retain all immutable inputs through
   submission retirement.
5. For fixed draws forward `SetFVF`, `SetMaterial`, `SetLight`, `LightEnable` and
   `SetClipPlane` to provider-owned fixed state, initialize defaults once, expand
   FVFs and pack independent fixed constants. Apply the verified **Metal-only**
   texture-stage enum-table repair described in the fixed report; the existing
   tentative zero tables must remain unchanged for GL/OFF. Correct COLORVERTEX
   is 141; render state 147 is AMBIENTMATERIALSOURCE. Do not claim DX7 engine
   support until those state/loading connections are made.

The reconstructed DX7 sampler loop currently does not forward
`RB_ChangeGenTexCoords`; WS33 must connect that state too. Preserve the verified
position/reflection flag distinction when packing texture-stage state.

Fixed input packing is intentionally local: `ExpandFVF` supplies position in
attrib[0], normal in [3], point size in [4], diffuse/specular in [5]/[6], and
texcoords in [8..15], mirrored into the named input fields. Use that helper or
the same convention for fixed vertices. Programmable declaration fetching uses
ARB's different normal/color/secondary/fog slots [2]/[3]/[4]/[5]. Matching raster
varying tags permit mixed stage linking; they do not make these two buffer-0
input representations interchangeable.

Draws are still intentionally absent in this wave. Successful shader fixtures
and linking do not imply a rendered Toujane scene, combined PSO/target state
parity or full-frame GL equivalence. The orchestrator merges focused commits in
order, keeps the small native CMake/setup additions, and wires the documented
loading/state seams with WS31/WS33.
