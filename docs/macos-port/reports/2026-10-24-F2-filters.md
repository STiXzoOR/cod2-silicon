The extracted `RB_ApplyFilterPasses` helper matches the original inlined glow
loop: initial source, alternating feedback targets 11/12, final destination,
code constants starting at slot 35, white draw color, stats target 10 and one
end-surface call per pass. Glow flips the last pass only when the last-glow
flag is set and the accumulated pass count is even. Full Gaussian filtering
uses its own pass-count parity and does not update the glow counter. No mode
branch exists in these original bodies.

The X-axis maximum-radius equality branch differs in expression form
(`sqrt(max*max-maxSquared)` versus zeroing), but the checked binary32
constants make the subtraction exactly zero; no observable finite result
difference was found, so it was left unchanged.

  filter array. This is inherited behavior, not corrected or claimed safe
  by this fidelity unit; changing the original pass budget needs a separate
  explicit behavioral decision. No such extreme-radius test was run here.

  change was added.
