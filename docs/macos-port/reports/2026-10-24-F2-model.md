# F2 model transforms, bounds and skinning

Base: `dfa30ec`. Behavior changed in `r_model.c`; `r_staticmodel.c` stays unchanged. The Mac 1.3 i386 executable is the authority. Private bounded assembly and test output are in `~/Library/Application Support/CoD2-native-decomp/F2-model.noindex/`.

## Repairs and evidence

- `R_UpdateXModelBounds` now reserves 64 typed `DSurface` records. The old 134-byte array overflowed when the real `DObjGetSurfaces` wrote an allowed 64-surface model. ASan caught the first write beyond byte134 before the repair. Mac passes the array at `0xd083c–0xd0854`; the 64-record contract is shared with the other material/surface callers.
- Bounds calculation claims state0→1, skips states above1, and waits for the owner when another calculation won. Both skin entrypoints claim state2→3 and wait/return after losing that claim. Mac: `0xd0789–0xd07c3`, `0xd0f9a–0xd0fcc`, `0xd166c–0xd169e`. The reconstructed calls swapped exchange/comparand and omitted the wait/return. Seven production fixture cases failed before repair: bounds claim/completed/contention and both dynamic/static skin claim/contention. Contention is deterministic callback simulation; this is not a threaded stress test.
- Static-surface caching checks technique12/grid lighting only for DX7. DX9 goes directly to the cache. Mac compares renderer2 at `0xd13dd` and jumps to the technique check at `0xd1448`; both renderer choices were reversed. Both focused cases failed before repair.
- `R_SkinRigidXModelCmd` adds the squared quaternion terms before subtracting from one (`0xd26c0–0xd26d5`, `0xd2703–0xd2714`, `0xd273a–0xd2756`). A unit quaternion fixture observed `0.49999997` instead of exact `0.5` before repair.
- Blended DX7 primary positions use sequential scalar addition (`R_SkinXSurfaceSkinned`, `0xd22eb` onward). Blended DX9 extra influences use the paired SIMD grouping (`0xd2215–0xd2226`). The DX9 output also retains the weighted homogeneous fourth component rather than forcing1 (`0xd21ca`, `0xd2223–0xd222a`, store at `0xd2060`). Three exact synthetic arithmetic cases failed before repair; the W case uses quantized weights summing to65535/65536.

The changes retain native pointer/record sizes, existing cache capacities, per-context buffers, normal/tangent primary-bone behavior and all OFF code. No shared headers, allocation policy, fallback, normalization or extra capacity guard was added.

## Comparison limits and follow-up

Registration, material selection, rigid/entity composition, debug-box/axis construction, model enumeration, static maximum-LOD surface allocation, surface record packing, command types2/6/7 and valid-input skin branch layout were compared. `R_InitStaticModelDynamicData` retains its native-sized allocation and original max-over-LODs/zero-fill sequence (`0xfbd7a–0xfbe2d`); no new test was added for unchanged behavior.

This is not whole-module parity. Remaining differences need their own evidence before edits:

- `R_LockSkinnedCache` uses a native lock argument and GPU-sync-dependent DISCARD/NOOVERWRITE selection; Mac1.3's no-argument body always requests0x2000 (`0xd0054`). Its lifecycle must be reconciled with `r_rendercmds.c` and the native buffer implementation before changing that contract.
- Native overflow warnings share one throttle variable and use different wording, while Mac has separate per-operation throttles. No diagnostic-only tests or edits were added.
- Original material/surface allocation overflow comparisons are unsigned; the current signed comparisons agree for ordinary nonnegative bounded counters. Signed overflow/malformed counters and high-bit mask shift UB were not closed in this unit.
- Temporary skin storage lives in the native `DxGlobals` lifecycle rather than original per-backend storage. It was preserved with the existing initialization/reset code outside this unit.

No library or cache rewrite, extra safeguards, or coverage-only fixtures were built. There is no original capture or every-input floating-point equivalence claim.
