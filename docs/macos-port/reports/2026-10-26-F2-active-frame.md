# F2 active-frame reconciliation — 2026-10-26

`CG_DrawActiveFrame` now performs the Mac 1.3 snapshot entity preparation pass
and conditionally integrates view recoil. Both changes are inside `COD2_X64`
guards. This is a bounded reconciliation of this function and its recoil
handoff, not a claim of parity for `cg_view_mp.c` or all cgame code.

## Mac evidence and changes

Authority: the owned Mac 1.3 i386 binary, symbol
`CG_DrawActiveFrame` at `0x1d4a50`. Private instruction excerpts and test logs
are under `~/Library/Application Support/CoD2-native-decomp/F2-active-frame.noindex/`.
No reference source or disassembly is included in the repository.

- `0x1d50b3–0x1d5130` iterates `nextSnap->entities` in snapshot order, obtains
  each numbered entity's client DObj, updates it and processes its notetracks
  when present, then calculates lerp positions for entity types at most 9.
  This pass precedes recoil, skeleton reset, packet entities, and input. The
  native function previously omitted the entire pass.
- `0x1d4c7b` tests `0x80` at snapshot byte `0x1a`. Since `ps.pm_flags` starts
  at snapshot byte `0x18`, the mask is **`0x800000`**, not `0x8000`.
  When absent, the original clears both kick vectors. When present, the
  original integrates the existing vectors instead of clearing them.
- `0x1d4ed3–0x1d5355` selects the previous predicted player's viewmodel weapon,
  advances recoil in at most 5 ms steps including the remainder, and uses
  2400 as the weapon-zero centering acceleration. Other weapons use hip or
  ADS view-kick center speed, selecting ADS only above weapon position 0.5.
  Movement toward zero is multiplied by 0.06; crossing zero clears angle
  and velocity; exceeding ±10 clamps the angle and clears velocity. The
  unordered crossing comparison also clears NaN results. Constants
  were read directly from the binary's literal storage.

The whole function was compared, including its early exits, time rollback,
interpolated LOD origin, shellshock selection, third-person selection,
prediction/view/audio order, test FX timing, late mounted-player processing,
viewlocked entity handling, animation dumping, delayed HUD drawing, invalid
weapon selection, and `bgs` cleanup. No additional behavioral discrepancy was
found in those stages. The original's unconditional final zero in invalid
weapon selection is preserved. The existing optional rumble hook remains a
port feature. `renderScreen == 0` still returns before world rendering,
including the intentional cubemap path.

The producer/consumer handoff was also checked: `CG_FireWeapon` feeds
`BG_WeaponFireRecoil` into `cg->kickAVel`; the Mac producer at `0x7b298` writes
negative pitch, yaw, and negative half-yaw. Prediction occurs after this
frame's recoil integration, so a newly predicted shot contributes on the next
eligible frame. `CG_DrawActive` at `0x1cefca` adds `kickAngles` and
`offsetAngles` before `CL_SetUserCmdAimValues`. Those producer/consumer files
required no changes for this handoff.

### Entity-animation consumers and mover adjustment

Restoring the active-frame preparation pass exposed two existing native consumer
faults. `CG_Player` and `CG_Corpse` still advanced each body's DObj after
`BG_PlayerAnimation`, compensating for the formerly absent preparation pass.
Native rendering now leaves advancement to the restored pass; the legacy calls
remain unchanged behind `!COD2_X64`. Original Mac `CG_Player` at `0x1e6834`
(825 instructions, 4,277 bytes) and `CG_Corpse` at `0x1e78ea` (100 instructions,
409 bytes) contain no calls to `DObjUpdateClientInfo` at `0x41e74`. The duplicate
native calls would advance visible bodies twice and discard notifications from
the second update before the next frame's notification consumption.

`CG_CalcEntityLerpPositions` now resolves native corpse state through
`cgs->corpseinfo[entityNum - 64]`. Its helper had retained the Mac 1.0 negative
base `-0x6bec`, combined with a widened native stride. For corpse entity 64,
that selects byte 51,220 of cgs rather than the native corpse array at 172,168
(the layout measured in WS38), corrupting unrelated cgs storage while leaving
the real corpse animation fields stale. Mac 1.3 instructions at
`0x163d88–0x163dcb` use `cgs + 0x15594 + entityNum * 1208`, equivalent to the
original corpse array at 164,756 plus `(entityNum - 64) * 1208`.

The immediately adjacent mover function had two confirmed differences.
`CG_AdjustPositionForMover` at `0x163b3f` checks `nextState.eType`, whereas the
native function checked `currentState.eType`. Native now follows the pending
snapshot when an entity enters or leaves mover type 6. Instructions
`0x163bca–0x163c20` subtract trajectory origins first, then add the caller's
position. Native now preserves that arithmetic order, avoiding cancellation of
small input positions against large mover origins. Both changes preserve the
legacy source under `COD2_X64=OFF`.

`tests/camera/run_entity_animation.py` compiles the complete production player
and entity translation units plus production `com_math.c`, with ASan/UBSan and
the actual stock/CoD2x engine flags. Animation advancement, trajectory evaluation
and renderer services are synthetic boundaries; no body-animation clip, skeleton,
rendered image, or full active-frame loop is simulated. Existing active-frame
fixtures cover loop wiring. The new tests execute the real preparation consumers,
player/corpse render functions, corpse lerp and mover adjustment:

- Player and corpse each advance exactly once before animation goals and scene
  submission. The player case consumes a real `CG_ProcessClientNoteTracks`
  left-hand notification and observes the dirty flag before the render phase.
- Corpse slots 0 and 7 update move direction, lean and player angles at the typed
  destination; all bytes outside those five floats remain unchanged.
- Mover entry/exit transitions use the next state, and rejected entity 1022
  preserves input position while clearing optional angle deltas.
- Rounding-sensitive inputs exercise all three axes with explicit expected IEEE
  bits `3f808000`, `3f800000`, `bf800000`; expected values are not calculated by
  repeating the production expression. Input/output aliasing is exercised.

All eight groups pass in stock and CoD2x. Against historical `4818b1a`, seven
fail and the bounds control passes in both configurations. Before the mover
repair alone, its three regression cases failed while the other five passed.
The pre-existing player `byte *`/`GfxEntity *` and turret
`XAnim *`/`XAnimTree *` compiler warnings remain visible and unchanged.
