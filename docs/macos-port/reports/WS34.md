# WS34 — Metal targets, copies, clears, gamma and camera gate

Branch: `port/metal-targets`. Base: WS29 `351fe82`.

## Implementation and authority

ABI 1 remains unchanged. No integration-owned header, engine header, original
GL method body or top-level CMake file changed. Native implementation lives in
`src/Mac/Metal/metal_targets.m` and `metal_target_shim.m`; its local contract is
`metal_targets.h`. The macOS client CMake fragment adds only these two sources
and their ARC flags. The only existing production source edits are a guarded
resource registration in `metal_backend.m` and guarded startup/stop/deferred-clear
hooks in `metal_frame.m`.

The helper retains the core's exact `MTLDevice`, Metal 4 command transport,
queue and event. It does not introduce another queue or timeline. Preparation
builds the original clear/copy/gamma MSL, all 70 color-format/mask pipeline
variants, 512 depth/stencil mask states and two samplers before rendering.
Encoding looks up prepared objects; it never calls a shader or pipeline
compiler. Argument tables, immutable constant/upload buffers and temporary
alias-copy textures are ordinary per-operation resources.

Implemented ABI resource-shim methods:

- `CreateRenderTarget`, `CreateDepthStencilSurface`,
  `CreateOffscreenPlainSurface`, and a standalone fallback for render-target
  `CreateTexture` with shared mip-level surface views.
- `SetRenderTarget(0)` and `SetDepthStencilSurface`, including binding
  references and the target-change viewport reset.
- `Clear`, `ColorFill`, `StretchRect`, `UpdateSurface`,
  `GetRenderTargetData`, `SetGammaRamp` and `GetGammaRamp`.
- Real target-surface `GetDesc`, rectangular `LockRect` and `UnlockRect`,
  including read-only locks and partial immutable buffer uploads to mip views.
  Plain-surface pool metadata is retained. X8 formats produce opaque alpha
  through the clear/copy/upload paths.

Logical formats 21/22 map to BGRA8, 32/33 to RGBA8 and 113 to RGBA16F.
75 maps to D32F/S8. Depth-only 70/71/77/80/82 map to D32F. This preserves
floating depth values rather than quantizing them to emulated D16/D24 storage;
the reference fixture allows two D24 units for this precision difference.
There is no sRGB transform, allocation padding to powers of two or implicit
texture Y flip. Target views carry explicit mip/slice and logical extent.

Each helper operation ends its encoder. Subsequent render passes load and
store every active aspect and issue conservative Metal 4 queue-stage/device
visibility barriers. Full clears use attachment load clears; rectangular,
channel-masked and stencil-masked clears use prepared scissored draws. A
small color target sharing larger scene depth clears only its logical extent.
Cropped views of a larger native backing also use scissored emulation; an
actual GPU regression failed before this fix and passes for color/depth and
depth-only clears.
Depth-only attachments work without a dummy color texture.

`Clear` decodes **flags, ARGB, float depth, stencil** in that order. The real
ABI fixture supplies deliberately different depth and stencil values, covering
the WS18 ordering repair. Like the current GL method, device Clear overrides
write masks and skips the special `flags=1, color=0` case. `ColorFill(0)` really
clears transparent black. The lower helper additionally exposes masks for
independent GPU fixtures and intended stencil emulation; current production
GL ignores clear rectangles and does not apply all stencil draw state. The
explicit CGL references therefore test intended rectangle/stencil behavior
rather than claim those incomplete GL methods already implement it.

Compatible equal-size unfiltered color copies use Metal 4 compute copies.
Scaling, filtering and format conversion use prepared sampling pipelines.
Aliased allocations, including **different native texture-view objects with
the same parent allocation**, stage their source first. Neither overlapping
copies nor sampled copies read an active destination attachment.
X8-to-alpha conversions use the prepared copy shader even when the native
backing contains arbitrary alpha from a draw. Direct3D defines a default of
one for undefined channels.
[Microsoft D3DFORMAT](https://learn.microsoft.com/en-us/windows/win32/direct3d9/d3dformat).
The raw-alpha regression failed before the fix and passes after it. Existing
GL maps X8 to physical RGBA; this fixture proves intended logical D3D format
semantics, not arbitrary backing-alpha equivalence to that GL mapping.

Submitted target references receive the core's exact completion value through
the resource callback and remain alive until submission ownership is released.
When both producer slots are unavailable, clears retain their target identities,
rectangles and values in order; a later submission flushes them. The queue is
bounded at 256 clears so a quarantined GPU cannot grow CPU ownership forever.
Explicit screenshot readback drains earlier work, obtains a slot, flushes
deferred clears and reads the actual pre-gamma scene. Cancellation/resize/stop
release deferred ownership. Resize retains the exact device/queue/event and
offscreen assets; the stable backbuffer identity resolves the replaced scene
texture and refreshed dimensions.
Unsealed frame work is canceled on resize under the core's existing policy;
the continuity fixture verifies previously committed asset contents.

`SetGammaRamp` now reaches the existing display/presenter ramp instead of the
core's former no-op. `GetGammaRamp` returns the saved 768 RGB16 values. The
prepared synthetic gamma pass uses the same byte-indexed per-channel lookup
as `macos_gamma.h`; it preserves source contents. Engine screenshots continue
to read the scene before the presenter's gamma pass.

The narrow `metal_target_types.h` boundary avoids the engine's Carbon/STABS
aliases colliding with Foundation/Metal SDK types. `target_layout.c` checks
every size, alignment and field offset against `common_types.h`; these are
local validated boundary types, not engine layout replacements.

## Post effects and what WS33 can rely on

The source audit was checked against `r_rendertarget.c`,
`RB_SetShadowCookieCmd`, `RB_ApplyLatePostEffectsCmd`, the glow/filter code and
the channel-mixer material references in `rb_backend.c`. Shadow cookies have
a 128x128 color target and depth attachment; glow/filter targets share the
scene depth at smaller extents. Late effects copy the scene with a linear
`StretchRect` and then issue material draws, often using feedback textures.
Bloom cutoff/desaturation, sky bleed, blur and channel mixing are shader and
draw operations already produced by the engine, not distinct ABI target calls.

WS34 provides those attachments, clears, copies, feedback lifetime and pass
boundaries. Their material arithmetic and complete visible effect parity need
WS32 shaders, WS31 state/PSOs and WS33 draws. No substitute bloom/channel-mix
algorithm was installed that would bypass the original material path.
The clear-only engine still cannot certify those effects or the three Toujane
views. The synthetic gamma path is fully verified independently of draws.

Before any game resource is created, compose WS30 explicitly:

```c
MacMetalTargets_Install(&ws30ResourceOps, ws30ResolveTarget);
```

`ws30ResolveTarget` must return a **borrowed native allocation**, with mip,
slice and logical extent, backed by the core's same Metal device. Renderable
allocations need render-target usage; sampled allocations need shader-read
usage and mip/slice view support. The targets provider deliberately does not
cast WS30's private payload structure. It keeps WS30 upload/lock/unlock
callbacks, forwards other shim calls and chains `submitted(value)`.
The chained callback runs before target-held COM references are released.
A synthetic temporary target whose last owner is the pending submission
verifies that the base callback can still find its sidecar; the regression
failed before this callback-order repair.

ABI 1 has one resource-provider slot. Independent static constructors are
insufficient: a later WS30 installation can replace WS34. The orchestrator
must invoke the composition once all provider tables/resolvers are available.
When a resolver is installed, RT texture creation goes through WS30; the
standalone fallback exists for this branch's boot and isolated fixtures.

For each real draw, WS33 can call `MacMetalTargets_BeginDraw(draw)`, configure
the returned Metal 4 render encoder, encode the draw, then call
`MacMetalTargets_EndDraw(encoder)` before returning. It uses the snapshot's
color[0]/depth surfaces, preserves contents and owns submission references.
It does not configure viewport/scissor, PSO, depth/stencil state, samplers,
shader registers, geometry or topology; those remain WS31/WS32/WS33 work.
Resolve render-target textures through `MacMetalTargets_Resolve` when binding
them for sampling. Sampling logical X8 formats must supply alpha one; a raw
native BGRA/RGBA allocation alone does not enforce this after arbitrary draws.
A material that reads the same active attachment still
needs a distinct feedback intermediate; the copy helper handles this hazard
for its own operations but cannot discover arbitrary shader feedback.

Unsupported requests return failure rather than pretend success: MSAA,
multiple color targets, shared handles, unknown target formats, depth-format
stretch copies, and direct locks on standalone RT texture objects (lock their
returned level surface). Non-RT textures/uploads and their locks belong to
WS30. MetalFX, EDR and MSAA were not implemented.

## ABI proposals and merge notes

No ABI-1 header change is proposed for target operations. The local resolver,
composition and draw-pass helpers work around the single resource-provider
slot without depending on another provider's payload. GPU lifecycle/clear
flush hooks are weak defaults in the core frame translation unit and strong
definitions in the target provider, so existing isolated core/presenter tests
continue to link without WS34. Keep these hooks when merging frame changes.

The golden receipt needs a reviewed integration-owned **diagnostic** seam at
common engine screenshot/frame preparation, plus deterministic scene replay.
Its exact JSON fields and observation requirements are documented in
`metal-goldens.md`; copying requested pose/time values into an evidence receipt
is explicitly forbidden. This diagnostic need does not justify altering the
frozen renderer ABI or weakening the camera gates.

Merge the focused commits on this branch, including the provider registration,
frame lifecycle/clear flush edits, native CMake entries and CTest targets.
Combine source-list additions with other providers rather than replace them.
The draw provider must end every returned encoder before core commit, fence,
present, readback or target/copy operation. Conservative per-operation splitting
is a correctness baseline; no performance claim or pass-coalescing optimization
is made. No system packages were installed, no other worktree was accessed,
and nothing was pushed or published. No licensed or derived game content is
included in the commits.
