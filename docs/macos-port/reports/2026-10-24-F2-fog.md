# F2: renderer fog reconciliation

Compared all seven functions in `r_fog.c` and `rb_fog.c` at `e31321c`
against the Mac MP 1.3 i386 instructions. No behavioral discrepancy was found;
engine code and the existing fixture remain unchanged. The Linux dedicated
reference contains neither translation unit.

| Mac symbol / address | Reconciled behavior |
| --- | --- |
| `R_ClearFogs` / `0xd2830` | Clears the five 32-byte fog records and resets the selected index. |
| `R_SetFog` / `0xd286c` | Stores BGR plus opaque alpha; selects technique 1 and clamps density to 1 at density >= 1, otherwise technique 2 with the supplied density; marks registered, draws sky, and disables screen clearing. Unordered density takes the latter branch. |
| `R_SwitchFog` / `0xd2936` | Uses registered current slot 2 as transition source in slot 3; otherwise copies the selected slot and forces an immediate transition. Copies the selected destination to slot 4 and sets or clears both times. |
| `R_ArchiveFogState` / `0xd2a9e` | Archives the 160-byte fog array, then the four-byte selected index, through the supplied callback. |
| `RB_FogOffset` / `0xfaa68` | Returns zero when the fog dvar is disabled; otherwise returns the backend technique offset. |
| `RB_UpdateFogColor` / `0xfaa8c` | Skips index zero; selects black for source 2 or source 0 with blend mask 0x20, otherwise backend color; forces opaque alpha and only sends changed cached color. |
| `RB_SetIteratorFog` / `0xfab32` | Skips technique type 3, absent technique, or unregistered fog; supplies color constant 29 and range/density constant 28. Renderer mode 2 selects linear D3D mode 3 for technique 1, exponential mode 1 otherwise; updates only changed cached color, mode, start/end, or density. |

The literal at `0x326184` is exactly `0.003921568859368563f`; `0x326188`
is 1, `0x3261a0` is zero, and `0x32b780` is the sign-bit mask used for
negation. Color ordering, reciprocal/multiply order, D3D state numbers
`0x22`, `0x24`–`0x26`, and `0x8c` agree. Existing typed native dvar accesses
for `r_zfar` and `r_rendererInUse` remain intentional LP64 mappings. The
zero `r_zfar` fallback and unordered float comparisons agree with the original.

## Validation

Ran the existing fixture twice, once without and once with
`-DCOD2_CODX=1`, using the standalone command from
`tests/lp64/renderer/run.sh`:

```sh
evidence="$HOME/Library/Application Support/CoD2-native-decomp/F2-fog.noindex"
taskpolicy -b nice -n 19 clang -arch arm64 -std=c11 -ffp-contract=off \
  -DCOD2_X64=1 -DGL_SILENCE_DEPRECATION -Isrc -Isrc/headers \
  -Wno-deprecated-non-prototype -Wno-incompatible-pointer-types \
  -Wno-typedef-redefinition -Wno-duplicate-decl-specifier -Wl,-dead_strip \
  -fsanitize=address,undefined tests/lp64/renderer/fog_mapping.c \
  -o "$evidence/fog_mapping-stock"
"$evidence/fog_mapping-stock"
```

Both executions exited zero without sanitizer diagnostics. This fixture proves
the existing native far-plane fallback/override constants and renderer mode
selection; the remaining coverage above is instruction comparison, not a new
runtime oracle. There is no red/green fix because no defect was identified.
`unifdef -UCOD2_X64` followed by `cmp` against `e31321c` was exact for both
engine files; `git diff --check` passed. Private assembly and validation notes
are under the evidence directory above. No full build, game run, or image
comparison was performed for this unchanged-code unit. Original Mac render
capture parity and the unavailable Linux object comparison remain unverified.
