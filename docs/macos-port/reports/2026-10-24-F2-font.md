# F2 font console commands and loader comparison — 2026-10-24

Base: `dfa30ec`; unit workspace: `faithful-renderer-font`.
`behavior_changed: true` for native console icon decoding only.

`R_GetConsoleIcon` decoded the low operand byte as the command. Mac 1.3
`0xec7ff` loads AL as the operand and `0xec802` loads AH as the command;
`0xec89f–0xec8a2`, `0xec911–0xec914`, and `0xec92c–0xec92f` repeat that split
for the optional color/flip paths. The native switch now selects the high byte,
while material index, RGB and dimension operands still use the low byte.
The original OFF source is unchanged.

A synthetic seven-entry console icon at the public `R_DrawConsoleText` and
`R_ConsoleTextWidth` boundaries demonstrated six failures before the engine edit:
material index 5 was not selected; width 32 and height 24 were wrong; RGB operands
128/64/192 were ignored; horizontal UV flip was absent; measured width was not 2.
Each assertion ran in a separate process against actual production source.
All six pass under ASan/UBSan with both stock and CoD2x engine flags after the fix.
No original executable rendering or capture parity is claimed.

The remaining comparison found no additional valid-input defect:

- Glyph direct lookup (32–127), extended binary search, and glyph 14 fallback
  agree (`R_GetCharacterGlyph`, `0xec2d8`, including its inline copies).
- Registration cache/capacity/error paths (`0xec36a`), duplication preserving an
  existing name or allocating a copied name (`0xec422`), empty initialization,
  and count reset on shutdown agree. Native pointer-sized font copies remain.
- Normalized scale is multiply by 48 then divide by pixel height (`0xec548`);
  height and draw-command forwarding agree. Existing native zero returns in
  reconstructed int declarations represent original void entrypoints.
- Text width newline/color skipping and glyph advance accumulation agree
  (`0xeca5e`). Console string conversion, trailing-space trimming, RGB commands,
  and icon boundary detection agree (`0xec5da`). The console width's unscaled
  icon width and use of the post-consumption character budget are original
  behavior (`0xecbde`). Console draw sizing, baseline, UV flip and advancement
  agree (`0xece9a`). Float literals were read from the binary: 48, 1/32,
  0.003921568859368563, 0.800000011920929, and -0.5.
- `R_LoadFont` (`0xfb970–0xfba6f`) agrees for valid disk images: open/read/close,
  16-byte header, inserted four-byte glyph-pointer slot, strings relative to
  expanded base+4, and material registration. Native pointer marshalling,
  bounds validation and short-read rejection are intentional existing changes.
  `r_font_load_obj.c` needs no edit. The unused local `R_ResolveFont` helper has
  no callsites and was left unchanged.
