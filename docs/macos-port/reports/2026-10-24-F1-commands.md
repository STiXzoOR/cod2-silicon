# F1 command processing reconciliation

Compared `src/PC/qcommon/cmd.c` at `83aacfb` with the Linux 1.3 guide and
Mac 1.3 i386 assembly. No new behavior defect was confirmed, so no engine or
test code changed. Existing native fixes already restore escaped quotes and
termination at the token limit. This is a bounded source/assembly review,
not a claim of whole-engine replay parity.

## Behavior checked

- Tokenization and its three public wrappers match the Mac flow: signed-byte
  whitespace outside quotes, literal bytes inside quotes, escaped quotes,
  adjacent quoted/unquoted tokens, line/block comments (including `/*/`),
  the unparsed final argument when a token limit is supplied, and rejection
  after 512 tokens when input remains. Exactly 512 tokens ending at NUL are
  accepted. Authority: `Cmd_TokenizeStringInternal` at `0x4e914`, especially
  `0x4e988–0x4e99f`, `0x4ea08–0x4ea1c`, `0x4ea85`, and `0x4ea8f`.
- Buffer initialization, append, insertion, immediate execution, draining,
  and wait match. Insertion adds a newline and permits an exactly full
  buffer; append rejects an exactly full buffer. Semicolons split only
  outside quotes; CR/LF split even inside quotes. The scanner counts every
  quote, including escaped quotes, and does not parse comments. Long lines
  use the original 4095-byte chunk behavior. Authority: `Cbuf_Init`
  `0x4e7da`, `Cbuf_AddText` `0x4e7fe`, `Cbuf_ExecuteText` `0x4f150`,
  `Cbuf_ExecuteInternal` `0x4eeae`, and `Cmd_Wait_f` `0x4ebf0`.
- `exec` and `vstr` preserve argument checks, filename extension handling,
  dvar type checks, insertion order, and resource release. Successful
  `exec autoexec` already prints the resolved `autoexec.cfg`; no logging
  fix is needed. Authority: `Cmd_Exec_f` `0x4f3b6` and `Cmd_Vstr_f` `0x4f296`.
- Command add/remove, shutdown, enumeration, listing, autocomplete metadata
  and file-list dispatch, and initial registrations match the Mac linked-list
  operations, case-sensitive registration, filters, and call arguments.
  Authority: `Cmd_RemoveCommand` `0x4eaec`, `Cmd_Shutdown` `0x4eb4c`,
  `Cmd_ForEach` `0x4eb88`, `Cmd_List_f` `0x4ec20`, and registration/autocomplete
  bodies at `0x4f012–0x4f14c`, plus `Cmd_Init` `0x4f508`.
- Command dispatch matches move-to-front lookup, case-insensitive execution,
  null-handler fallthrough, dvar/client/server precedence, and forwarding,
  subject to the intentional boundaries below. The Mac body at `0x4ed1c`
  has no `UI_GameCommand` step; the Linux guide's extra step is not imported.
  Argument count/access/buffer wrappers and `Cmd_Args` match for valid
  argument indices. The port's `Cmd_ArgsBuffer` expresses the same join/copy
  operation; no separate Mac symbol was found for that convenience wrapper.

## Existing intentional differences retained

Native argument access rejects negative indices with unsigned bounds; the
Mac uses signed bounds (`Cmd_Argv` `0x4e7c2`, `SV_Cmd_Argv` `0x4e870`,
and their buffer wrappers). The native behavior is retained. Pointer-sized
command links are required by LP64. Native dedicated builds omit client
handling and print unknown commands. PunkBuster pre-execution/event dispatch
is absent at the existing unsupported PunkBuster boundary. CoD2x retains its
competitive-server wait restriction and policy tokenizer, including URLs
and bounded output. These are not claimed equal to stock Mac behavior.

## Validation and limits

Both existing tokenizer fixture runs passed with ASan/UBSan and the actual
stock/CoD2x engine compile flags. Compile databases were copied read-only
from the integration checkout into private evidence directories:

```sh
taskpolicy -b nice -n 19 python3 tests/fidelity/run.py --build "$HOME/Library/Application Support/CoD2-native-decomp/F1-commands.noindex/stock" --test tokenizer
taskpolicy -b nice -n 19 python3 tests/fidelity/run.py --build "$HOME/Library/Application Support/CoD2-native-decomp/F1-commands.noindex/codx" --test tokenizer
```

Each reported `tokenizer: 0 failures`. A temporary production-function
characterization also confirmed resolved exec logging and insertion before
queued commands; it required no change and was not added as a new harness.
`unifdef -UCOD2_X64` plus `cmp` against `83aacfb` passed for the unchanged
`cmd.c`. This does not prove Linux object identity. No game, full build,
replay, or original-binary execution was run for this report. External
filesystem, dvar, game-command, and platform implementations were not
reconciled by this unit. Private assembly and fixture outputs remain under
`~/Library/Application Support/CoD2-native-decomp/F1-commands.noindex/`.
