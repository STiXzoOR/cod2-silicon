# F1c — script reconciliation (2026-10-23)

Branch `decomp/f1-script`, starting at `02094fd`. Private evidence is in
`~/Library/Application Support/CoD2-native-decomp/F1-script.noindex/` (`E` below).
The Mac 1.3 instructions are authoritative; Linux 1.3 was read to compare logic.
No reference source, assembly, decompiler output or game data was copied into Git.

## Behavior changes and Mac evidence

- Compiler developer-call state uses `developer_statement`, leaving program
  length intact. Mac `EmitCall` at `0x95af0` reads `_scrCompilePub+0x28`, writes
  states 1/2 at `0x95b50`/`0x95bbb`, then clears it at `0x95a7a`.
- Constant-folded vectors reverse collected components (`EvalPrimitiveExpression`
  `0x92759` writes output+8, then `0x92764` subtracts four). Negating INT_MIN
  wraps as `NEG EAX` at `0x925ae`. Branch merges use child public counts, as
  `EmitIfElseStatement` at `0x984*` does.
- The lexer had swapped notify and waittillmatch tokens. Mac yacc cases `0x49`
  and `0x4b` return `0x146` and `0x148`. Notify now retains its event-list head;
  waittillmatch emits `0x77`, count byte and `0x34`, matching `EmitStatement`
  at `0x97b7a`/`0x97bea`/`0x978da`. Notify source positions identify the event.
  The waittill keyword no longer adds an unnecessary string reference.
- Scanner EOF, last-match, refill reserve and embedded-NUL transitions follow
  Mac `yyparse` (`0x10fc08`, `0x10fdd8`, `0x10fd22`). EOF identifiers and NUL
  inputs previously hung. Buffer-allocation failure restores the original
  diagnostic and exit 2 (`yy_create_buffer`, `0x10be2a`).
- Compiler operands/backpatches, switch tables, archived VM records, literal
  vectors and packed field metadata use byte copies. Mac i386 MOV/MOVSS permits
  these unaligned addresses; arm64 C typed dereferences were undefined. Operand
  widths, five-byte stack records, arena offsets and code-position handles stay
  32-bit. Existing WS80/WS84/WS87 operand conventions are retained.
- VM notify matching rejects a shorter argument list before all expected values
  match (`VM_Notify`, `0x82231`–`0x82234`). Notify saves/reloads frame position
  around callbacks (`0x84b48`–`0x84b62`). External execution restores the caller's
  original sentinel type (`0x86f38`/`0x86f8f`), and depth overflow releases
  remaining arguments and pushes undefined (`0x87002`–`0x87050`).
- VM object, method, increment/decrement, waittill, notify, endon, switch and
  excess-parameter failures use script error dispatch and Mac operand indexes,
  replacing fatal candidate messages. Relevant checks include object dispatch
  at `0x86499`–`0x864b9`. Function-pointer errors preserve the Mac error index and
  ownership/pop order. Wait conversion follows MULSS/ADDSS/floorf/CVTTSS2SI at
  `0x859e3`–`0x85a05`, including 32-bit integer wrapping and signed range errors.
- Variable object errors now call `Scr_Error` (`Scr_EvalVariableObject`
  `0x887ca`/`0x887d2`, `Scr_EvalFieldObject` `0x8fbf9`/`0x8fc01`). Array equality
  checks `evaluate`, as `0x908a2` does. Array-reference/clear errors restore
  release order and avoid creating undefined entity fields (`0x8f01a` through
  `0x8f394`, `0x91992` through `0x91f3c`). Returning errors during evaluation
  retain the Mac arithmetic dispatch. ClearObject detaches children before
  releasing values (`0x8f560`).
- Adjacent hash/collision siblings retain their updated links during removal.
  `MakeVariableExternal` writes sibling links at `0x8cc22`/`0x8cc36`/`0x8cc43`/
  `0x8cc57`, then reads the hash at `0x8cc5e`. The native early snapshot lost an
  aliased previous-sibling update. A two-key collision test reproduced broken
  reverse traversal before the correction.
- Thread diagnostics use full 32-bit positions (`ThreadInfoCompare`, `0x883c5`)
  and grouped stack/object/endon accounting (`Scr_DumpScriptThreads`, `0x8a467`,
  `0x8a970`, `0x8b0f9`, `0x8b249`). RuntimeError tests dialog pointer nullness,
  including an empty non-null dialog (`0x9bacc`/`0x9bacf`).
- Memory-tree free nodes use the original score-priority radix order, replacing
  LIFO order. `MT_AddMemoryNode` `0x43fbc`–`0x44003` computes
  `65536-node-popcount+(1<<ctz)`; `0x44085`/`0x44088` promote the larger score.
  Force rebuilding avoids already-free enclosing blocks (`0x451b3`–`0x4525c`).
- String restart splices through the successor's next link (`SL_Init`,
  `0x43be1`), and accepts valid handle 65535 (`SL_FindStringOfLen`, `0x42e80`).
  Vector formatting preserves packed literal reads (`0x43e0a`/`0x43e15`/`0x43e20`).
- Animation external-reference registrations reset after load owners are
  released, avoiding process-total exhaustion after 16383 registrations. Mac
  raw pointers have no accumulated side table. Undefined-animation errors regain
  their leading 0x15 (`Scr_LoadAnimTreeAtIndex`, `0x9cc73`/`0x9cc82`).

Default builds already compile out the existing DBG probes; they were left
unchanged. No new production diagnostics were added.

## Intentional differences and limits

Script values/arena and code-position handles remain 32-bit. Native pointer
tables, monotonic timeout service and packed access adapters are intentional.
Existing invalid-ID guards and the safe total-length string concatenation guard
remain: Mac `Scr_EvalPlus` at `0x9042d` tests only the left length and can overflow
its 8192-byte buffer. The animation table still has 16383 simultaneous external
slots per load; the existing 128-tree invalid-input guard remains.

Mac Bool diagnostics are capitalized; Linux uses lowercase (Mac literal
`0x248a70`). Mac generic VM longjmp handling at `0x8622f` clears temporary opcode
state before RuntimeError; Linux performs opcode-specific cleanup. The native
generic Mac path is retained. Malformed direct-opcode tests intercept the error
and do not establish parity of every invalid-script continuation. Optional
debugger operation remains unverified.
