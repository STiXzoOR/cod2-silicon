# F2 snapshot flag fidelity — 2026-10-26

`behavior_changed: true`. This bounded batch fixes two misplaced byte masks in
native `cg_snapshot_mp.c`. It does not complete the cgame reconciliation.

## Behavior and Mac evidence

- `CG_SetNextSnap` now tests `ps.pm_flags & 0x400000` before deciding whether
  to run player-state transitions outside prediction. Mac 1.3
  `__Z14CG_SetNextSnapP10snapshot_t` at `0x1df0bb` tests byte
  `nextSnap + 0x1a` with `0x40`. Since `ps.pm_flags` starts at snapshot offset
  `0x18`, the whole-field mask is `0x400000`. Its taken branch reaches
  `CG_TransitionPlayerState` at `0x1df0e5`. The previous native `0x40`
  skipped damage/event delivery for the actual flag and triggered it for an
  unrelated low bit. Demo, nopredict and synchronous controls retain their
  existing transition path. The prediction path already recognizes
  `0x400000` as nonpredicted.
- `CG_ResetEntity` now tests corpse `nextState.eFlags & 0x80000`. Mac 1.3
  `__Z14CG_ResetEntityP9centity_s` at `0x1decb4` tests byte `cent + 0xfa`
  with `8`, two bytes into `nextState.eFlags` at `0xf8`. This branch copies
  the player's client info, preserves the corpse's animation-tree pointer,
  clones the source tree at `0x1ded38`, and zeros `previousEventSequence`
  at `0x1ded3d`. The other branch copies client info only for an empty model
  or changed client identity and advances the event cursor to the incoming
  sequence at `0x1dedf2`–`0x1dedf8`, suppressing old corpse events.

Both masks were independently checked in the private assembly exports
`discovery/functions/1dde08.json` and `1ddb10.json`; symbol identities were
checked with `nm -U` filtered to lowercase `t`. No private assembly or
reference source is included here. No CoD2x override for these three
functions was found in its source, so the fixes apply to both native modes.

## Focused verification

The fixture includes the complete production snapshot and playerstate
translation units. Synthetic snapshots exercise the actual
`CG_TransitionPlayerState` and `CG_DamageFeedback`: assertions cover event
number/parameter delivery, notification, attacker time, damage pitch and
expiry, while keeping the old player state intact. Corpse assertions cover
model copying, animation clone arguments and synthetic clone state,
preserved tree pointers, backpack attachment removal, retained helmet,
client identity and the previous-event cursor. Unrelated services are
stubbed; unexpected use of those services fails the fixture.

Run from the integration checkout:

```sh
root=/Users/stix/Projects/cod2-native-wt/decomp-f1-script
evidence="$HOME/Library/Application Support/CoD2-native-decomp/F2-snapshot.noindex"
for mode in stock codx; do
  build=build-macos
  if [ "$mode" = codx ]; then build=build-macos-codx; fi
  taskpolicy -b nice -n 19 python3 tests/camera/run_snapshot.py \
    --compile-db "$root/$build/compile_commands.engine.json" \
    --output "$evidence/red-$mode" --baseline d497f60
  taskpolicy -b nice -n 19 python3 tests/camera/run_snapshot.py \
    --compile-db "$root/$build/compile_commands.engine.json" \
    --output "$evidence/green-$mode"
done
```

The red stock and CoD2x runs were executed **before editing production code**.
Each failed the four intended assertions: `transition-high`,
`transition-low`, `corpse-high`, and `corpse-low`. The eight controls passed:
ordinary/demo/nopredict/synchronous/null-dvar transitions and
ordinary/empty-model/mismatched-client corpses. An initial fixture compile
caught a name collision with the engine's `corpse` typedef; the helper was
renamed before obtaining the behavioral reds.

After the fix, all 12 cases passed in each mode with AddressSanitizer and
UndefinedBehaviorSanitizer enabled, using the actual engine compile flags
and `-UNDEBUG`. Summary logs are `red-stock.log`, `red-codx.log`,
`green-stock.log`, and `green-codx.log` in the private evidence directory;
individual assertion logs are under the corresponding run directories.

The compared `COD2_X64=OFF` source is identical to `d497f60`. `unifdef`
returns 1 when it removes conditional sections; that is not a comparison
failure. This proves source preservation for this file, not the unavailable
Linux i386 binary comparison.

## Limits

No live game, demo playback, animation rendering, replay oracle, full build
or broad merge gate was run by this unit; integration owns those checks.
Animation-tree cloning is observed through a synthetic callee, not the
production animation implementation. Other snapshot raw offsets, client
layout handling, respawn behavior and killcam animation logic were read for
context and left outside this change. No layout cleanup, guards or new
runtime abstraction was added. The full F2 and multiplayer fidelity plan
remain unfinished.
