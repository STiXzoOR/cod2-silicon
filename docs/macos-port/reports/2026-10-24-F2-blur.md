# F2: native blur and post-effect composition

`r_blur 2` produced a black scene while the HUD remained visible. Diagnosis
revealed missing target resolves, missing viewport changes, and incompatible
texture coordinates. Each repair exposed the next defect; live captures and
focused tests record those stages. `behavior_changed`: yes.

Work started clean at `314d0e6` on `decomp/f2-renderer-blur`. The orchestrator
fast-forwarded the worker to `06275b3` before authorizing image-filter edits,
preserving the preceding filter fixes. No worker commits or staging.

## Observed chain and Mac evidence

1. With glow disabled, a one-frame trace recorded two Gaussian draws and a
   final `feedbackblend`. At the first outgoing-target boundary, framebuffer
   center RGB was `(124,118,102)` while the entire ping-pong texture was zero.
   The next pass sampled that zero texture and produced black. Both boundary
   probes reported no GL error. The native device setter merely assigned a
   pointer. Mac `CDirect3DDevice::SetRenderTarget` (`0x15500`) calls
   `CopyColorToRenderTargetTexture` at `0x15586` before changing a non-backbuffer
   target, unless `g_InhibitCopy`. The helper copies the current read buffer
   into the old target texture at `0x14848`, preserving the active texture and
   unit-zero binding. Restoring that operation removed the all-black output.
2. The resulting image was enormously magnified. Numeric probes showed both
   320x180 filter targets still using a 1280x720 GL viewport. The engine writes
   its viewport cache before `RB_UpdateViewport`, so its equality check skips
   the device call. Mac's setter itself obtains the new surface description
   and calls `SetViewport` (`0x15536–0x15574`). Restoring that operation removed
   the repeated fourfold viewport magnification.
3. The remaining crop came from applying original power-of-two UV fractions
   to native textures without padding: `(0.625,0.703125)` at 1280x720, repeated
   through filtering and final composition. `CDirect3DTexture` constructs the
   storage with the requested width/height; render-target creation passes the
   exact viewport extent (or quarter extent). The existing native
   `RB_UpdateViewportConstants` adaptation explicitly follows this contract.
   Native filter/composition coordinates now span the entire texture. The
   next live capture showed the complete scene at the correct scale.
4. That complete scene was upside down. Mac final blur and glow draws use
   `t0=0` and positive `t1` (`0xda553/0xda545` and `0xda7c4/0xda7b8`). Native
   composition reversed these coordinates unnecessarily. Restoring their
   order is separately covered by a failing command-level assertion and the
   intermediate upside-down capture.
5. The same Mac command compares the minimum virtual radius against the
   requested radius at `0xda4ae`, branching when the request is *smaller*.
   It reduces blend alpha and raises the filter radius to that minimum at
   `0xdaad1–0xdab02`. Native code had the comparison reversed and omitted the
   radius assignment. Both below- and above-threshold cases failed before
   correction. This restores the original policy; it adds no new radius cap.
