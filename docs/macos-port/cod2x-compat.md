# CoD2x compatibility and remaining gaps

The comparison target is upstream `callofduty2x/CoD2x` main at `f0db15cf2be98b6bf5621a4a2076998cdb600c4b` (2026-11-12), version **1.4.7.1-test.1, revision 7**. Its latest release is **v1.4.6.8, revision 6**, 49 commits earlier. Read the pinned files with `git show origin/main:<path>` in the reference checkout; its working branch is older. Upstream has no license permitting source transplantation: this port implements behavior independently.

**0.3.0 does not yet provide complete latest-upstream parity.** Native client/server version state remains revision 6. Revision7 server player-info emission is implemented, but native xray/head labels/health presentation and the corresponding client decoder are missing. Upstream-main servers therefore still reject the native revision 6 client at their extension-version check. Released revision 6 servers pass that particular check; authentication, passwords, bans, pure files, match credentials and proprietary protection are separate.

“Source compared” below describes the cited branch/formula/registration only. “Scoped check” means a named existing fixture or loopback case ran. Neither means every game scene, device or remote service was verified. Replays/build status belong in the final parity-fix evidence and release verification; this matrix must not turn a successful build or one joined server into a full-parity claim. Paths prefixed U are from the pinned upstream `src/`; N paths are native `src/PC/` unless `platform/`, `unix/`, or `Mac/` is specified.

## Connection and identity

Connect packets use stock protocol 118. Discovery accepts/requests 118 and 120. `protocol_cod2x` is an extension revision, not a replacement netchan protocol. Upstream main requires 7; release 1.4.6.8 requires 6; neither applies an upper-bound revision check. There is no renderer-feature attestation in that version gate. Raising the number alone would permit that gate while leaving missing behavior, so it would not establish complete revision 7 support.
