# Camera attachment fixture

This fixture includes the complete production `cg_view_mp.c` and links the
production quaternion, matrix, axis and angle functions from `com_math.c`.
Tag/skeleton services and shake/perturb effects are controlled synthetic inputs.
Expected positions and axes are explicit analytic values informed by the owned
Mac 1.3 camera branches; they are not generated by the implementation under test.

Run serially in stock and CoD2x modes with the actual engine compile databases:

```sh
taskpolicy -b nice -n 19 python3 tests/camera/run.py \
  --compile-commands /absolute/private/stock/compile_commands.engine.json \
  --output /absolute/private/qa.noindex/camera-stock
taskpolicy -b nice -n 19 python3 tests/camera/run.py \
  --compile-commands /absolute/private/codx/compile_commands.engine.json \
  --output /absolute/private/qa.noindex/camera-codx
```

The runner remaps the database's source/include paths into its own checkout,
compiles the production camera translation unit with the actual Release flags,
then builds the fixture with assertions, ASan and UBSan. All outputs stay outside
the checkout. `--baseline <commit>` selects historical camera source for the
fixture, and `--case weapon` (or another group) narrows execution.

The seven groups cover optional weapon tags, weighted quaternion axes, bone zero,
nonzero bone selection, rotated parent axes, mounted-player tags and entity/client
selection, mounted firing jitter and exclusion in third person, the required-tag
drop error, activation/fallback gates, shake/viewmodel/attachment/perturb ordering,
normal viewport/FOV and intentional CoD2x orbit behavior. A snapshot spectator
transition also checks the reference's exclusion of normal view-height offsets.

These tests prove the controlled camera contracts. They do not validate real tag
assets, skeleton animation readiness, live mounted aiming, hit registration,
renderer output, or original-versus-native runtime replay.
